## Overview

This program demonstrates how to insert a new element at a specific index in a pre-allocated Go slice. It shows how the built-in `copy` function can shift a subslice one position to the right into allocated buffer space, vacating a slot where the new element is directly assigned.

## How it works

The `main` function serves as the application entry point:
- Sets `n := 7` and allocates an integer slice `arr := make([]int, n+1)` with space for 8 elements.
- Populates the first `n` elements (indices `0` through `6`) with values `1` through `7`, leaving the final index (`7`) initialized to zero.
- Prints the initial slice: `[1 2 3 4 5 6 7 0]`.
- Configures target index `idx := 0` and insertion value `x := 100`.
- Calls `copy(arr[idx+1:], arr[idx:])`. Go's `copy` copies elements from source `arr[0:]` to destination `arr[1:]`. Because `copy` safely handles overlapping slices, this shifts all existing elements one position to the right.
- Assigns the new value: `arr[idx] = x`.
- Prints the resulting slice: `[100 1 2 3 4 5 6 7]`.

## Key excerpt

```go
func main() {
	// insertion, n elements, n + 1 room
	n := 7
	arr := make([]int, n+1)

	for i := 0; i < n; i++ {
		arr[i] = i + 1
	}

	fmt.Println(arr)

	idx, x := 0, 100
	copy(arr[idx+1:], arr[idx:]) // right shift
	arr[idx] = x                 // insert

	fmt.Println(arr)
}
```

## Things to watch

- **Pre-allocation requirement:** This implementation assumes the slice has pre-allocated capacity and an extended length (`n + 1`). If `copy(arr[idx+1:], arr[idx:])` were called on a slice of length `n`, the destination slice would have length `n - 1 - idx`, and the final element would be truncated without growing the slice.
- **Idiomatic dynamic insertion in Go:** In general Go code where slices grow dynamically, inserting an element at index `i` is typically written as `append(arr[:i], append([]int{x}, arr[i:]...)...)` or with Go 1.21's `slices.Insert(arr, i, x)`.

## Terms

- **copy:** A built-in Go function that copies data between slices, safely handling overlapping memory regions within the same backing array.
- **Default zero value:** Uninitialized elements in Go primitive slices default to 0 for numeric types.
