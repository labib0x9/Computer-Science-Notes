## Overview

This program demonstrates Named Return Value Optimization (NRVO) and copy elision in modern C++. By comparing the memory address of a local `std::vector` inside a function with the memory address of the receiving variable in the caller, it illustrates how optimizing compilers construct return objects directly in the caller's stack frame, eliminating redundant copy and move operations.

## How it works

The program includes `<bits/stdc++.h>` and imports namespace `std`.

The function `RLE`:
- Takes a reference to a vector `vector<int>& arr`.
- Declares a local vector `rle` of type `vector<array<int, 2>>`.
- Prints the memory address of `rle` on the stack: `printf("%p\n", &rle)`.
- Returns `rle` by value.

In `main`:
- Allocates an initial integer vector `arr{1, 2, 3, 3, 4}`.
- Calls `auto r = RLE(arr)`, receiving the returned vector into `r`.
- Prints the memory address of `r`: `printf("%p\n", &r)`.
- Returns `0`.

If compiled with copy elision disabled (`-fno-elide-constructors`):
```bash

```
The addresses will differ, as `rle` resides in `RLE`'s stack frame and is moved into `r` in `main`.

## Things to watch

- **Non-standard header:** Uses `#include<bits/stdc++.h>`, which is a GCC/Clang internal implementation header commonly used in competitive programming but unsupported on standard MSVC.
- **C++ Standard differences:** While mandatory copy elision for prvalues was standardized in C++17, NRVO (for named lvalues like `rle`) remains an optional compiler optimization under the C++ standard, though nearly all modern compilers implement it by default.

## Terms

- **Copy Elision:** A compiler optimization that avoids copying or moving objects even if the copy/move constructor has side effects.
- **NRVO (Named Return Value Optimization):** A form of copy elision where a named local variable returned from a function is constructed directly in the caller's storage.
