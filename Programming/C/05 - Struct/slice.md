2. `AppendSlice(s, val)`: Checks if `s->len == s->cap`. If the capacity is exhausted, it doubles `s->cap` and resizes `s->arr` using `realloc(s->arr, sizeof(int) * s->cap)`. It then places `val` at index `s->len` and increments `s->len`.
3. In `main`:

   - Elements are sequentially appended, causing dynamic capacity reallocation.
   - Elements and internal state are printed.
   - Allocated memory is freed.

## Key excerpt

```c
typedef struct Slice {
	int* arr;
	int len, cap;
} slice_t;

void AppendSlice(slice_t* s, int val) {
	if (s->len == s->cap) {
		s->cap *= 2;
		s->arr = (int*)realloc(s->arr, sizeof(int) * s->cap);
		if (s->arr == NULL) {
			perror("realloc failed");
			exit(EXIT_FAILURE);
		}
	}
	s->arr[s->len++] = val;
}
```

## Things to watch

- **realloc return check**: Assigning `s->arr = realloc(s->arr, ...)` directly can cause a memory leak if `realloc` fails, because the original pointer in `s->arr` would be overwritten with `NULL`. In production code, store the result in a temporary pointer first.
- **Pass-by-pointer**: Functions modifying struct fields (`AppendSlice`) take a pointer `slice_t*` rather than a struct value copy.

## Terms

- **realloc**: Standard C library function that resizes an existing heap memory allocation while preserving existing data.
- **Geometric Resizing**: Doubling capacity upon exhaustion, ensuring an amortized $O(1)$ append time complexity.
