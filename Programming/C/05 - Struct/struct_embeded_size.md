## How it works

The code defines two structs:
- `pair_t`: Contains two integers `first` and `second` (total 8 bytes).
- `pool_elem_t`: Contains a `bool allocated` (1 byte) followed by an embedded `pair_t obj` (8 bytes). Due to alignment requirements, the compiler inserts 3 padding bytes after `allocated` so that `obj` starts at an address divisible by 4, making `sizeof(pool_elem_t)` equal to 12 bytes.

A global array `pool_elem_t object_pool[10]` is declared and initialized to zero.

In `main`:
- It prints `sizeof(pair_t)` (8 bytes).
- It prints `sizeof(pool_elem_t)` (12 bytes).
- It prints the total size of the global array `sizeof(object_pool)` ($10 \times 12 = 120$ bytes).

## Things to watch

- **Implicit padding**: Even though `bool` is 1 byte and `pair_t` is 8 bytes, the struct size is 12 bytes due to 3 padding bytes added for 4-byte member alignment.
- **Global zero initialization**: Global arrays initialized with `{0}` are placed in the `.bss` section of the binary, taking zero disk space in the executable file.

## Terms

- **Composition**: Embedding one struct as a direct field of another struct.
- **Alignment Padding**: Unused bytes inserted by the compiler between struct fields to ensure hardware-friendly memory addresses.
