## Overview

This program demonstrates how the C compiler applies alignment padding to struct members and how GCC's `__attribute__((packed))` attribute overrides this behavior to produce tightly packed structures with zero padding bytes.

## How it works

The program defines two identical sets of fields across two structs:
- `struct A`: Default compiler alignment. Contains `bool a` (1 byte + 3 padding), `int b` (4 bytes), `char c` (1 byte + 7 padding), `long long d` (8 bytes), and `char e` (1 byte + 7 trailing padding). Total size is 32 bytes on 64-bit systems.
- `struct B`: Declared with `__attribute__((packed))`. The compiler disables all padding bytes. Fields are packed tightly: 1 + 4 + 1 + 8 + 1 = 15 bytes.

In `main`, the program prints `sizeof(struct A)` and `sizeof(struct B)` to highlight the dramatic size reduction.

## Things to watch

- **Unaligned memory access penalty**: Packed structs save memory (e.g. for network packet headers or binary disk serialization), but accessing unaligned fields can incur CPU performance penalties or trigger alignment faults on certain architectures (like older ARM or SPARC).
- **Compiler portability**: `__attribute__((packed))` is a GCC/Clang extension; MSVC uses `#pragma pack(push, 1)`.

## Terms

- **Struct Packing**: Instructing the compiler to eliminate alignment padding between struct fields.
- **Memory Alignment**: Placing data in memory at addresses that are multiples of the data size for optimal CPU memory bus efficiency.
