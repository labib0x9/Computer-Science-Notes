## Overview

This program demonstrates how file descriptor status flags are combined using bitwise OR (`|`) or masked out using bitwise AND NOT (`& ~`). It illustrates how failing to read existing flags with `F_GETFL` causes accidental loss of earlier configuration.

## Concepts used

- Creating anonymous pipes via `pipe(pipe_fd)`
- Combining flags with bitwise OR: `flags | O_NONBLOCK`
- Clearing flags with bitwise bitmask: `flags & ~O_NONBLOCK`
- Interrogating flags with `fcntl(fd, F_GETFL, 0)`

## How it works

1. It creates an anonymous pipe with `pipe(pipe_fd)`, yielding read descriptor `pipe_fd[0]` and write descriptor `pipe_fd[1]`.
2. It fetches existing flags: `flags = fcntl(pipe_fd[0], F_GETFL, 0)`.
3. It demonstrates combining flags: `fcntl(pipe_fd[0], F_SETFL, flags | O_NONBLOCK)` adds non-blocking mode safely.
4. It demonstrates inspecting flags using bitwise AND: `if (flags & O_NONBLOCK)` confirms non-blocking status.
5. It demonstrates clearing flags: `flags &= ~O_NONBLOCK` followed by `F_SETFL` restores blocking mode.

## Things to watch

- **Pipe descriptors**: When creating a pipe, `pipe_fd[0]` is dedicated for reading and `pipe_fd[1]` for writing. Setting non-blocking mode on the read end prevents `read()` from hanging when the pipe buffer is empty.

## Terms

- **Bitwise Masking**: Using bitwise operations (`&`, `|`, `~`) to toggle individual bit flags within an integer bitfield.
- **Pipe**: A unidirectional data channel used for inter-process or inter-thread communication.
