## Overview

This program demonstrates how to map a file into the process virtual address space in read-only mode using the `mmap` system call in C. Memory-mapping files allows reading file data directly via memory pointers without intermediate kernel-to-userspace buffer copying (`read` system calls).

## Concepts used

- File sizing via `fstat`
- Memory protection flags (`PROT_READ`)
- Mapping visibility flags (`MAP_PRIVATE`)
- Unmapping memory pages with `munmap`

## How it works

1. It opens `test.txt` with `open("test.txt", O_RDONLY)`.
2. It calls `fstat(fd, &st)` to obtain the file size (`st.st_size`).
3. It invokes `mmap(NULL, st.st_size, PROT_READ, MAP_PRIVATE, fd, 0)`:
   - `NULL`: Lets the OS kernel choose the virtual memory address.
   - `st.st_size`: Number of bytes to map.
   - `PROT_READ`: Pages may be read.
   - `MAP_PRIVATE`: Creates a private copy-on-write mapping.
   - `fd, 0`: Source file descriptor and byte offset.
4. The returned pointer `data` is dereferenced like a normal character array (`printf("%s\n", data)`).
5. It unmaps the memory via `munmap(data, st.st_size)` and closes `fd`.

## Key excerpt

```c
    char* data = mmap(NULL, st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
    if (data == MAP_FAILED) {
        perror("mmap");
        close(fd);
        return 0;
    }

    // Direct memory access
    write(STDOUT_FILENO, data, st.st_size);

    munmap(data, st.st_size);
    close(fd);
```

## Expected behavior (from reading the code, not run)

- If `test.txt` exists, maps its pages and prints its text content to stdout.
- If `test.txt` cannot be opened or is empty (0 bytes), `mmap` fails or is skipped.

## Things to watch

- **Zero-byte files**: Passing length 0 to `mmap` causes it to fail with `EINVAL`. Always verify `st.st_size > 0` before mapping.
- **Null-termination**: Files mapped with `mmap` are not automatically null-terminated; printing with `%s` in `printf` without a bounds limit can read past the mapped page and cause a `SIGSEGV`. Prefer `fwrite` or `write(STDOUT_FILENO, data, size)`.

## Terms

- **mmap**: POSIX system call that establishes a direct mapping between a process address space and a file or device.
- **Zero-copy**: An I/O technique that avoids copying data between user and kernel memory buffers.
