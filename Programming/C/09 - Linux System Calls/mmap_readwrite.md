## Overview

This program demonstrates how to perform direct in-memory file updates in C using `mmap` configured with `PROT_READ | PROT_WRITE` and `MAP_SHARED`. Modifications to the memory pointer are flushed back to the underlying physical disk file using `msync`.

## Concepts used

- Read-write memory mapping (`PROT_READ | PROT_WRITE`)
- Shared mapping mode (`MAP_SHARED`) to write changes back to disk
- In-place memory mutations via pointers
- Explicit synchronization of memory to disk using `msync(..., MS_SYNC)`

## How it works

1. It opens `test.txt` in read-write mode: `open("test.txt", O_RDWR)`.
2. It obtains the file size via `fstat`.
3. It maps the file: `mmap(NULL, st.st_size, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0)`.
   - `MAP_SHARED`: Crucial flag ensuring writes to the memory buffer affect the file and are visible to other processes mapping the same file.
4. It modifies bytes directly in memory: `data[0] = 'H'; data[1] = 'I';`.
5. It invokes `msync(data, st.st_size, MS_SYNC)` to flush dirty OS page cache pages to disk synchronously.
6. It calls `munmap` and closes `fd`.

## Key excerpt

```c
    char* data = mmap(NULL, st.st_size, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (data == MAP_FAILED) {
        perror("mmap");
        close(fd);
        return 0;
    }

    // Direct in-memory file modification
    data[0] = 'H';
    data[1] = 'I';

    // Flush dirty pages to disk
    if (msync(data, st.st_size, MS_SYNC) == -1) {
        perror("msync");
    }
```

## Expected behavior (from reading the code, not run)

- Directly mutates the first two bytes of `test.txt` to `'H'` and `'I'`.
- Flushes the change to the filesystem.

## Things to watch

- **MAP_PRIVATE vs MAP_SHARED**: If `MAP_PRIVATE` was used, modifications would trigger Copy-On-Write (COW), modifying only private process memory without persisting changes to the disk file.
- **File size expansion**: `mmap` cannot expand a file past its existing size. To extend a file before mapping, use `ftruncate()` or `posix_fallocate()`.

## Terms

- **MAP_SHARED**: Shares this mapping with all other processes that map the same region; modifications are carried through to the underlying file.
- **msync**: Flushes changes made to a memory-mapped file back to the storage device.
