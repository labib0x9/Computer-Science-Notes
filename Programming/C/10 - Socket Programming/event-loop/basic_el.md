## Overview

This program demonstrates how to construct an asynchronous event loop on macOS and BSD systems using the `kqueue` kernel event notification interface. It uses a pipe to wake up the event loop thread from concurrent worker threads.

## Concepts used

- Kernel event notification with `kqueue()`
- Registering event filters with `EV_SET` and `kevent()`
- Inter-thread signaling via pipes (Self-Pipe / Worker-Pipe trick)
- Decoupling heavy background work from the event dispatch loop

## How it works

1. `pipe(pipe_fd)` creates a pipe; the read descriptor `pipe_fd[0]` is configured with `O_NONBLOCK`.
2. `kqueue()` creates a kernel event queue handle `kq`.
3. `EV_SET(&ev_set, pipe_fd[0], EVFILT_READ, EV_ADD, 0, 0, NULL)` configures an event filter to monitor `pipe_fd[0]` for readable data.
4. `kevent(kq, &ev_set, 1, NULL, 0, NULL)` registers the filter with the kernel.
5. A background worker thread (`pthread_create(&th, NULL, worker, NULL)`) executes tasks and writes a byte to `pipe_fd[1]` upon task completion.
6. The main event loop blocks on `kevent(kq, NULL, 0, &ev_list, 1, NULL)`. When the worker writes to the pipe, `kevent` unblocks immediately, reads the notification byte, and processes the result.

    // create kqueue
    int kq = kqueue();
    if (kq == -1) {

## Things to watch

- **Platform specificity**: `kqueue` is specific to BSD-derived operating systems (macOS, FreeBSD, OpenBSD). Linux systems use `epoll` (`epoll_create`, `epoll_ctl`, `epoll_wait`) or `io_uring`.
- **Draining the pipe**: When waking up from an event loop, always read all available bytes from the pipe until `EAGAIN` to prevent immediate re-triggering.

## Terms

- **kqueue**: A scalable event notification interface in BSD and macOS kernels.
- **Event Loop**: A programming construct that waits for and dispatches events or messages in a program.
