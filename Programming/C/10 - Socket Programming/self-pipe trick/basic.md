## Overview

This program demonstrates the classic UNIX "self-pipe trick". It shows how a unidirectional pipe (`pipe()`) enables threads or signal handlers to safely wake up an event loop that is blocked waiting on I/O multiplexers like `select()`, `poll()`, or `kqueue()`.

## How it works

1. The program allocates two file descriptors `int pipe_fd[2]`.
2. `pipe(pipe_fd)` creates a pipe where `pipe_fd[0]` is the read end and `pipe_fd[1]` is the write end.
3. The read end is added to an event multiplexer's watch set.
4. Whenever an asynchronous event occurs (such as a signal arriving or a worker thread completing a task), a single byte (e.g. `'W'`) is written to `pipe_fd[1]`.
5. The kernel wakes up the waiting multiplexer because `pipe_fd[0]` has become readable.
6. The event loop reads the byte from `pipe_fd[0]` and executes the corresponding action.

## Things to watch

- **Signal safety**: Writing a single byte to a pipe via `write()` is async-signal-safe, making the self-pipe trick one of the few robust mechanisms to convert asynchronous UNIX signals (`SIGINT`, `SIGHUP`) into synchronous event loop events.
- **Linux eventfd alternative**: On Linux, `eventfd()` is a lighter-weight alternative to `pipe()` that uses a single kernel object and file descriptor instead of two.

## Terms

- **Self-Pipe Trick**: A software design technique in UNIX programming that uses a pipe to wake up an I/O multiplexer from a signal handler or thread.
- **Async-Signal-Safe**: A function that can be safely called from within a signal handler without causing deadlocks or corrupting static state.
