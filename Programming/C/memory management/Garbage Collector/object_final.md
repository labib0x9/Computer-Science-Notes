## How it works

The collector architecture consists of:
1. Object model: Supports primitive types (`INT`, `FLOAT`), structured types (`ARRAY`, `VECTOR3`), and links all live allocations in an intrusive linked list via `object_t* next_in_pool`.
2. VM Roots: A static root array `vm_roots` models stack references currently in scope.
3. Mark Phase (`mark(object_t* obj)`):
   - Sets `obj->is_marked = true`.
   - Recursively traverses children: for `ARRAY`, marks every element in `data`; for `VECTOR3`, marks `x`, `y`, and `z`.
4. Sweep Phase (`sweep()`):
   - Iterates through the global object pool.
   - If an object is marked, resets `is_marked = false` for the next cycle.
   - If an object is unmarked, unlinks it from the pool, frees nested buffers, and deallocates the object with `free()`.
5. In `main`:
   - Allocates several objects, arrays, and vectors.
   - Adds some to roots and leaves others unrooted (orphaned).
   - Triggers `gc_collect()`, demonstrating automatic reclamation of orphaned memory.

## Key excerpt

```c
void mark(object_t* obj) {
	if (obj == NULL || obj->is_marked) return;

	obj->is_marked = true;

	if (obj->Kind == OBJECT_ARRAY) {
		array_t* arr = obj->data.v_array;
		for (int i = 0; i < arr->len; i++) {
			mark(arr->data[i]);
		}
	} else if (obj->Kind == OBJECT_VECTOR3) {
		vector3_t* vec = obj->data.v_vector3;
		mark(vec->x);
		mark(vec->y);
		mark(vec->z);
	}
}

void sweep() {
	object_t** current = &head_object;
	while (*current) {
		if (!(*current)->is_marked) {
			object_t* unreached = *current;
			*current = unreached->next_in_pool;
			free_object(unreached);
		} else {
			(*current)->is_marked = false;
			current = &(*current)->next_in_pool;
		}
	}
}
```

## Things to watch

- **Pointer to pointer linked list removal**: The sweep loop uses `object_t** current` to cleanly delete nodes from a singly linked list without requiring a special case for the head node.
- **Deep recursion risk**: Deeply nested object graphs can cause stack overflows during the recursive mark phase; production collectors typically use an explicit worklist stack or Deutsch-Schorr-Waite pointer reversal.

## Terms

- **Mark-and-Sweep**: A two-phase tracing GC algorithm that marks reachable objects from roots and sweeps through the heap to reclaim unmarked memory.
- **Root**: A pointer directly accessible to the runtime (e.g. stack variable or global) that serves as a starting point for reachability analysis.
