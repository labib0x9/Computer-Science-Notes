## How it works

The code walks through each memory management API:
1. `malloc`: Allocates uninitialized memory containing indeterminate values; pairs with `memset(ptr, 0, size)` or `calloc`.
2. `calloc`: Allocates memory and guarantees all bytes are initialized to zero.
3. `realloc`: Resizes a block, demonstrating how `realloc` copies data to a new location if the block cannot be expanded in place.
4. `free`: Releases memory back to the heap allocator. Setting `ptr = NULL` immediately after `free` prevents accidental dangling pointer dereferences.

## Key excerpt

```c
    // allocate memory for 1 int on heap..
    int *ptr = malloc(sizeof(int)); // garbage value
    if (ptr == NULL) {
        // malloc fails
    }

    memset(ptr, 0, sizeof(int)); // set to 0x00

    // calloc sets memory to 0
    int *calloc_ptr = calloc(5, sizeof(int));
    if (calloc_ptr == NULL) {
        // calloc fails
    }

    free(ptr);
    ptr = NULL;
    free(calloc_ptr);
    calloc_ptr = NULL;
```

## Things to watch

- **Always verify allocation**: On memory-constrained systems, `malloc` and `calloc` return `NULL` when memory is exhausted; failing to check for `NULL` causes immediate segmentation faults.
- **Set freed pointers to NULL**: In C, calling `free(NULL)` is safely defined as a no-op, whereas calling `free` on an already-freed non-NULL pointer causes undefined behavior (double-free crash).

## Terms

- **Heap**: The region of process memory used for dynamic memory allocation managed at runtime.
- **Double Free**: A memory error occurring when `free()` is called more than once on the same address without an intervening allocation.
