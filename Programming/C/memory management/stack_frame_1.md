## Overview

This program demonstrates how to measure stack frame allocation sizes and determine the stack growth direction (downward vs upward) by calculating the pointer difference between successive calls to `__builtin_frame_address(0)`.

## How it works

The function `stack_frame()` maintains a `static void* prev_sp = NULL`:
1. It reads `current_sp = __builtin_frame_address(0)`.
2. It calculates `diff = (char*) prev_sp - (char*) current_sp`.
3. If `prev_sp` was set by an earlier invocation, it prints the byte difference `Diff = %ld`.
4. It updates `prev_sp = current_sp`.
5. Functions `A()` and `B()` call `stack_frame()` at different call depths, printing the byte size allocated for the intermediary stack frame.

## Key excerpt

```c
void stack_frame() {
	static void* prev_sp = NULL;
	void* current_sp = __builtin_frame_address(0);
	long diff = (char*) prev_sp - (char*) current_sp;

	if (prev_sp) {
		printf("Diff = %ld
", diff);
	}

	if (current_sp) {
		prev_sp = current_sp;
	}
}
```

## Expected behavior (from reading the code, not run)

- Calling `stack_frame` from a caller and then from a callee prints positive byte differences on architectures where stacks grow downward toward lower addresses.

## Things to watch

- **Downward growth**: On most modern architectures (x86, x86_64, ARM), the stack grows downwards toward lower numerical memory addresses. A positive difference indicates standard downward growth.

## Terms

- **Stack Growth**: The direction in memory (towards higher or lower addresses) in which new stack frames are pushed.
