## Overview

This program demonstrates the behavior of `static` local variables in C. It shows how the `static` storage-class specifier extends a local variable's lifetime to the entire duration of the program while preserving function-local visibility scope.

## Concepts used

- Static storage duration vs automatic stack storage duration
- Initialization in the initialized data segment (`.data`)
- State persistence across repeated function calls

## How it works

1. Inside `test()`, `static int a = 0;` is declared.
2. Unlike automatic local variables allocated on the stack, `a` is allocated once in the program's data segment at startup.
3. Each time `test()` is invoked:
   - `a += 10` modifies the existing value.
   - `printf("a = %d\n", a)` displays the updated value.
4. In `main()`, `test()` is called three times in succession, producing output `10`, `20`, and `30`.

## Key excerpt

```c
void test() {
	static int a = 0;	// stored at data segment, once created it persists on function calls...
	a += 10;
	printf("a = %d

}

int main() {

	test();	// 10
	test();	// 20
	test();	// 30

	return 0;
}
```

## Things to watch

- **Initialization timing**: The initialization expression (`static int a = 0;`) executes only once when the program is loaded, not on each function call.
- **Thread safety**: Static local variables are shared across all threads executing the function. Modifying static variables concurrently from multiple threads without synchronization creates data races.

## Terms

- **Static Storage Duration**: Memory allocated for a variable remains reserved for the entire lifetime of the program.
- **Data Segment (.data)**: The portion of the executable memory containing global and static variables initialized by the programmer.
