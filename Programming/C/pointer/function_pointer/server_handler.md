## How it works

The code defines:
1. `typedef int (*handler_func)(int client_id, char* body)`: Defines the standard signature for request handlers.
2. `Route` struct: Bundles `method`, `route` path, and the associated `handler` function pointer.
3. Handler functions: `handle_home` prints home route information and returns status 200.
4. `register_route`: Associates path strings with handler callbacks.

## Key excerpt

```c
typedef int (*handler_func)(int client_id, char* body);

typedef struct {
	char* method;
	char* route;
	handler_func handler;
} Route;

void register_route(char* method, char* route, handler_func func) {
	Route x = {method, route, func};
}

int handle_home(int client_id, char* body) {
	printf("Handling home route for client %d: %s
", client_id, body);
	return 200;
}
```

## Things to watch

- **Local struct scope**: In `register_route`, `Route x` is declared on the stack as a local variable; to preserve routes across requests, routes should be stored in a global array or dynamically allocated linked list.
- **String lifetimes**: `char* method` and `char* route` store raw pointers; if route strings are created dynamically, they must remain allocated for the server's lifetime.

## Terms

- **Router Table**: A lookup table matching request URLs to corresponding handling routines.
- **typedef**: C keyword used to create an alias for complex types like function pointers.
