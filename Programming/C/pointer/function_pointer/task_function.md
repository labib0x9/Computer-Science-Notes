## Overview

This program demonstrates how to package units of work into task structs using generic function pointers and `void*` arguments. This pattern is commonly used in thread pools, event loops, and asynchronous task queues in C.

## Source

[task_function.c](https://github.com/labib0x9/Programming-Notes/blob/main/Programming/C/pointer/function_pointer/task_function.c)

## Concepts used

- Task encapsulation via struct `task_node`
- Generic function pointer signatures (`void* (*func)(void* args)`)
- Argument bundling and type punning with `void*`

## How it works

The code defines `task_node`:
- `func`: A function pointer accepting `void*` and returning `void*`.
- `args`: A pointer to the arguments required by the function.

Two tasks are defined:
- `print`: Casts `args` to `int*`, prints the value, and returns `NULL`.
- `mult`: Multiplies the integer argument, allocates a new integer on the heap, and returns the result pointer.

In `main`:
- A `task_node` is instantiated with `print` and an integer argument.
- The task is dispatched by calling `node.func(node.args)`.

## Key excerpt

```c
typedef struct task_node {
	void* (*func)(void* args);
	void* args;
} task_node;

void* print(void* args) {
	int x = *(int*) args;
	printf("%d
", x);
	return NULL;
}
```

## Things to watch

- **Argument lifetime**: `node.args` points to memory that must remain valid until the task completes. Passing stack addresses of local variables that go out of scope before the task runs causes undefined behavior.

## Terms

- **Task Queue**: A queue of encapsulated executable units waiting to be processed by worker threads.
- **Closure Emulation**: Simulating function closures in C by pairing a function pointer with an explicit context/arguments pointer.
