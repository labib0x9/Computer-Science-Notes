## How it works

The code demonstrates two key concepts:
1. `test(void* a)`: Accepts a generic `void*`, explicitly casts it to `int*`, and dereferences it to print the integer value.
2. `return_from()`: Allocates local variable `int x = 40` on the stack and returns `(void*) (&x)`.
   - When `return_from()` exits, its stack frame is invalidated.
   - Returning `&x` creates a dangling pointer pointing to reclaimed stack memory.
   - Dereferencing this pointer later can cause undefined behavior, memory corruption, or segmentation faults.

## Things to watch

- **Dangling pointer hazard**: Never return the address of a local automatic stack variable. If data must outlive function execution, allocate it on the heap (`malloc`) or pass caller-allocated memory.
- **Pointer arithmetic on void***: In standard C, pointer arithmetic on `void*` (e.g. `ptr + 1`) is illegal because `sizeof(void)` is undefined (though GCC supports it as an extension treating `sizeof(void) == 1`).

## Terms

- **Dangling Pointer**: A pointer pointing to memory that has already been deallocated or reclaimed.
- **Stack Frame**: The block of stack memory allocated for a single function call to store local variables and return addresses.
