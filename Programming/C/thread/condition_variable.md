## Overview

This program demonstrates how to synchronize producer and consumer worker threads using POSIX condition variables (`pthread_cond_t`) and mutexes (`pthread_mutex_t`). It implements a bounded task queue where consumers sleep efficiently until tasks are enqueued.

## Concepts used

- POSIX condition variables (`pthread_cond_t`)
- Mutual exclusion with `pthread_mutex_t`
- Efficient thread sleep and wakeup (`pthread_cond_wait`, `pthread_cond_signal`)
- Preventing spurious wakeups with `while` loop checks
- Bounded task queue design

## How it works

1. It initializes `pthread_mutex_t lock` and `pthread_cond_t cond`.
2. A task buffer `Task queue[10]` stores up to 10 items.
3. Consumer (`worker`):
   - Acquires `lock`.
   - While `task_count == 0`, calls `pthread_cond_wait(&cond, &lock)`. This atomically releases the mutex and suspends the thread.
   - When signaled, re-acquires the lock, removes a task from the queue, decrements `task_count`, releases the mutex, and processes the task.
4. Producer:
   - Acquires `lock`.
   - Adds a task to `queue` and increments `task_count`.
   - Calls `pthread_cond_signal(&cond)` to wake one sleeping worker.
   - Releases `lock`.

void* consumer(void* args) {
   while (1) {
      pthread_mutex_lock(&lock);
      while (task_count == 0) {
         pthread_cond_wait(&cond, &lock);

## Things to watch

- **Spurious wakeups**: `pthread_cond_wait` can wake up even if no thread signaled the condition. Therefore, always evaluate condition predicates in a `while` loop (`while (count == 0)`) rather than an `if` statement.
- **Mutex ownership**: The mutex passed to `pthread_cond_wait` must be locked by the calling thread before calling wait.

## Terms

- **Condition Variable**: A synchronization primitive that allows threads to suspend execution until another thread notifies them that a condition has been met.
- **Spurious Wakeup**: A condition where a waiting thread unblocks without an explicit signal.
