## Overview

This program demonstrates concurrent execution in C using the POSIX threads (`pthreads`) library. It spawns two separate worker threads that run alongside the main thread, each periodically printing counters while sleeping for one second per iteration. Developers write code like this to explore basic multithreading primitives and observe how operating systems schedule independent execution paths within a single process.

## How it works

The program includes `<stdio.h>` for standard I/O, `<unistd.h>` for the `sleep` function, and `<pthread.h>` for thread management primitives.

The function `AliceTurn` serves as the thread routine for the first worker. It accepts a `void*` argument and iterates through a loop from index `0` to `10`. On every iteration, it pauses execution for one second using `sleep(1)`, prints the iteration value to standard output, and returns `NULL` upon completing all 11 iterations.

The function `BobTurn` serves as the thread routine for the second worker. It accepts a `void*` argument and loops from index `0` to `4`. On each step, it pauses execution for one second via `sleep(1)`, prints its counter value, and returns `NULL` when finished.

The `main` function serves as the application entry point. It declares a thread identifier `alice` of type `pthread_t` and calls `pthread_create(&alice, NULL, AliceTurn, NULL)` to start the `AliceTurn` routine concurrently in the background. Immediately following, it declares `bob` of type `pthread_t` and invokes `pthread_create(&bob, NULL, BobTurn, NULL)` to launch `BobTurn`.

Instead of blocking on thread joins, `main` invokes `sleep(10)` to keep the main thread and process alive while the background threads execute. When the sleep expires, `main` returns `0`, terminating the process and all associated threads.

## Things to watch

- **Sleep-based synchronization pitfall:** Using `sleep(10)` to wait for background threads is fragile. In C, when `main` returns, the entire process terminates immediately, killing all running threads regardless of their state. The proper synchronization mechanism is calling `pthread_join(alice, NULL)` and `pthread_join(bob, NULL)`.
- **Unchecked return values:** The calls to `pthread_create` do not inspect the return value. In production code, any non-zero return code signifies an error (such as resource exhaustion) that should be handled.
- **Platform and compiler flags:** POSIX threads require an operating system supporting POSIX APIs (such as Linux or macOS) and typically require linking with `-pthread` (or `-lpthread`).

## Terms

- **POSIX Threads (pthreads):** A standard execution model and C API for managing threads across POSIX operating systems.
- **Thread routine:** A function invoked as the entry point of a newly spawned thread, conforming to the signature `void* (*)(void*)`.
- **Race condition:** A flaw where system timing or thread scheduling influences the order or correctness of execution.
