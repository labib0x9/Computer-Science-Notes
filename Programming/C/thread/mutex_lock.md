## Overview

This program demonstrates how to eliminate data race conditions on shared memory in C using a mutual exclusion lock (`pthread_mutex_t`). Multiple threads increment a shared counter safely by synchronizing access around the critical section.

## Concepts used

- Shared mutable state across threads
- Mutex initialization via `PTHREAD_MUTEX_INITIALIZER`
- Critical sections protected by `pthread_mutex_lock` and `pthread_mutex_unlock`
- Deterministic concurrent arithmetic results

## How it works

1. It initializes a static global mutex `lock` using `PTHREAD_MUTEX_INITIALIZER` and a shared integer `count = 0`.
2. Worker function `Calc`:
   - Iterates 10,000,000 times.
   - Before modifying `count`, acquires `pthread_mutex_lock(&lock)`.
   - Increments `count++`.
   - Releases `pthread_mutex_unlock(&lock)`.
3. In `main`:
   - Spawns two threads running `Calc`.
   - Waits for both with `pthread_join`.
   - Because all modifications are serialized, `count` equals exactly `20000000`.

## Key excerpt

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
int count;

void* Calc(void* args) {
   for(int i = 1; i <= 10000000; i++) {
      pthread_mutex_lock(&lock);
      count++;
      pthread_mutex_unlock(&lock);
   }
   return NULL;
}
```

## Expected behavior (from reading the code, not run)

- Both threads complete 10 million increments each.
- The final printed counter value is exactly `20000000`.

## Things to watch

- **Lock contention**: Acquiring and releasing a mutex 20 million times in a tight loop incurs significant synchronization overhead. For high-frequency integer increments, consider C11 atomics (`stdatomic.h` with `atomic_fetch_add`) which execute without mutex overhead.
- **Deadlock risk**: If a thread crashes or forgets to call `pthread_mutex_unlock`, all other threads attempting to lock the mutex will block forever.

## Terms

- **Mutex (Mutual Exclusion)**: A locking mechanism used to synchronize access to a resource, allowing only one thread to enter a critical section at a time.
- **Critical Section**: A block of code that accesses shared mutable resources and must not be concurrently executed by more than one thread.
