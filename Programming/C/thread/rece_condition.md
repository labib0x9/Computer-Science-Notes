## Overview

This program demonstrates a classic data race condition in multi-threaded C programming. Multiple threads increment a shared global counter without synchronization, demonstrating lost updates and non-deterministic results.

## Concepts used

- Data races in concurrent programming
- Non-atomic read-modify-write operations (`count++`)
- Non-deterministic execution results
- Contrasting unprotected shared state with synchronized state

## How it works

1. A global integer `count` is initialized to 0.
2. In `Calc`:
   - Iterates 10,000,000 times, executing `count++`.
   - In machine code, `count++` requires three instructions: load from memory into CPU register, increment register, and store back to memory.
3. In `main`:
   - Two concurrent threads are spawned to run `Calc`.
   - Without synchronization, instruction interleaving causes both threads to read the same old value into their registers, overwrite each other's increments, and discard updates.
   - When joined, `count` evaluates to a random value significantly less than the expected 20,000,000.

## Key excerpt

```c
int count;

void* Calc(void* args) {
   for(int i = 1; i <= 10000000; i++) {
      count++;
   }
   return NULL;
}
```

## Terms

- **Race Condition**: A flaw in concurrent software where output is dependent on the uncontrollable timing and sequence of thread execution.
- **Atomic Operation**: An operation that completes in a single step relative to other threads without being interrupted.
