## Overview

This program demonstrates memory-mapped file I/O (mmap) in Go using the third-party library `github.com/tysonmote/gommap`. Memory-mapping maps a disk file directly into the process's virtual address space, allowing files to be manipulated as in-memory byte slices with kernel-managed page caching and disk synchronization.

## Concepts used

- Virtual memory file mapping (`mmap`)
- Memory protection flags (`PROT_READ`, `PROT_WRITE`, `PROT_EXEC`)
- Shared mapping (`MAP_SHARED`) vs. private copy-on-write
- Disk synchronization (`mmap.Sync(MS_SYNC)`)
- Binary integer persistence directly in mapped memory

## How it works

In `main`:
- Opens a file `data.index` with read/write/create flags.
- Truncates the file to 1024 bytes to pre-allocate disk blocks.
- Maps the file into memory using `gommap.Map(file.Fd(), gommap.PROT_READ|gommap.PROT_WRITE|gommap.PROT_EXEC, gommap.MAP_SHARED)`.
- Defers `mmap.UnsafeUnmap()` to release the virtual memory mapping upon exit.
- Copies string bytes directly into the mapped slice: `copy(mmap, []byte("Hello"))`.
- Flushes changes to disk with `mmap.Sync(gommap.MS_SYNC)`.
- Encodes an integer directly into mapped memory using `binary.BigEndian.PutUint64(mmap[0:4], uint64(123))`.
- Reads the integer back using `binary.BigEndian.Uint64`.
- Outlines dynamic resizing: unmapping, expanding file with `file.Truncate(2048)`, and re-mapping.

## Key excerpt

```go
	const mapSize = 1024 // bytes -> 1kb
	if err = file.Truncate(mapSize); err != nil {
		//
	}

	mmap, err := gommap.Map(
		file.Fd(),
		gommap.PROT_READ|gommap.PROT_WRITE|gommap.PROT_EXEC, // read, write mapped memory
		gommap.MAP_SHARED, // writes to memory also updates file
	)
	defer mmap.UnsafeUnmap() // Unmaps the memory region

	copy(mmap, []byte("Hello"))

	// Sync changes to disk
	if err := mmap.Sync(gommap.MS_SYNC); err != nil {
		//
	}
```

## Things to watch

- **Slice bounds checking on PutUint64:** `binary.BigEndian.PutUint64(mmap[0:4], ...)` attempts to write an 8-byte integer into a 4-byte slice slice `mmap[0:4]`, which triggers a runtime slice bounds out of range panic. Writing an 8-byte uint64 requires at least 8 bytes (`mmap[0:8]`).
- **File size prerequisite:** Memory mapping an empty 0-byte file causes bus errors (SIGBUS) when accessing mapped memory. Truncating the file beforehand is mandatory.

## Terms

- **mmap:** An operating system system call that maps files or devices into memory addresses.
- **MAP_SHARED:** Shares mapping updates with all processes and writes through to the underlying file.
