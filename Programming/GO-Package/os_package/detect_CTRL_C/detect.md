## Overview

This program demonstrates how to capture operating system termination signals (`SIGINT` and `SIGTERM`) in Go using the `os/signal` package. Intercepting these signals allows server applications, workers, and command-line tools to intercept user interrupts (`Ctrl+C`), perform cleanup, close database pools, and exit gracefully.

## Concepts used

- Signal interception via buffered channels
- `signal.Notify` subscription for `SIGINT` and `SIGTERM`
- Asynchronous signal reception in goroutines
- Clean program exit with `os.Exit(0)`

## How it works

In `main`:
- Creates a buffered channel `sigChan := make(chan os.Signal, 1)`.
- Calls `signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)` to route incoming interrupt signals into `sigChan`.
- Spawns a background goroutine:
  - Blocks on `sig := <-sigChan` waiting for an OS signal.
  - Upon arrival, prints `"Received: "` with the signal name.
  - Calls `os.Exit(0)` to terminate cleanly.
- Executes `select {}` on the main thread, blocking forever to keep the process alive until a signal is received.

## Key excerpt

```go
func main() {
	sigChan := make(chan os.Signal, 1) // Channel to receive OS signals
	signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM) // Subscribe to SIGINT (Ctrl+C) and SIGTERM

	go func() {
		sig := <-sigChan
		fmt.Println("Received: ", sig)
		os.Exit(0)
	}()

	select {} // Block forever
}
```

## Things to watch

- **Buffered channel requirement:** The signal channel passed to `signal.Notify` must have a buffer size of at least 1. If an unbuffered channel is used, signals may be dropped if the receiver is not immediately ready.

## Terms

- **SIGINT:** Interrupt signal (signal 2) sent by terminal when pressing `Ctrl+C`.
- **SIGTERM:** Generic termination signal (signal 15) sent by process managers like Kubernetes or systemd.
