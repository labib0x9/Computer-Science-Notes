## Overview

This program demonstrates how to measure the memory size of variables and struct instances in Go using `unsafe.Sizeof`. It reveals low-level details of data representation, showing how struct field alignment and padding determine the total byte footprint allocated by the Go compiler.

## How it works

Defines struct `type y struct { a int; b int64 }`.

In `main`:
- Declares `var x uint32`: a 32-bit unsigned integer (4 bytes).
- Declares struct instance `yy := y{2, 3}`.
- Prints `unsafe.Sizeof(x)`: returns `4`.
- Prints `unsafe.Sizeof(yy)`: on 64-bit architectures, `int` is 8 bytes and `int64` is 8 bytes, so `Sizeof(yy)` returns `16` bytes.

## Key excerpt

```go
type y struct {
```

## Things to watch

- **unsafe.Sizeof evaluation:** `unsafe.Sizeof` is evaluated at compile time by the compiler, not at runtime.
- **Pointer contents excluded:** If a struct contains a slice, string, or pointer, `unsafe.Sizeof` measures only the header size (e.g. 24 bytes for a slice), not the data allocated on the heap behind the pointer.

## Terms

- **unsafe.Sizeof:** Returns the size in bytes of the representation of the expression's type.
- **Alignment Padding:** Unused bytes inserted between struct fields by the compiler to ensure fields align to memory address boundaries matching their word size.
