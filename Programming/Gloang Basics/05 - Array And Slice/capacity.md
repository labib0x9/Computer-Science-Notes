## Overview

This program demonstrates how slice capacity is computed during sub-slicing operations in Go. It contrasts the standard 2-index slice syntax (`a[low:high]`) with the full 3-index slice syntax (`a[low:high:max]`) used to restrict slice capacity.

## Concepts used

- Slice length (`len`) vs capacity (`cap`)
- 2-index sub-slicing: `a[low:high]` where `cap = cap(a) - low`
- 3-index sub-slicing: `a[low:high:max]` where `cap = max - low`
- Protecting backing arrays against accidental mutation during `append`

## How it works

1. It initializes an 8-element slice `a1 := []int{1, 2, 3, 4, 5, 6, 7, 8}` (`len = 8, cap = 8`).
2. `a := a1[3:5]` takes elements from index 3 up to 5:
   - Length is $5 - 3 = 2$.
   - Capacity extends to the end of the backing array: $8 - 3 = 5$.
   - `fmt.Println(len(a), cap(a))` outputs `2 5`.
3. `a = a1[3:5:8]` specifies `max = 8`:
   - Length is 2, capacity is $8 - 3 = 5$.
   - If `max = 5` was used (`a1[3:5:5]`), capacity would be restricted to 2, forcing subsequent `append` calls to allocate a new backing array and preventing overwriting of elements in `a1`.

## Key excerpt

```go
func main() {
	// len = 8, cap = 8
	a1 := []int{1, 2, 3, 4, 5, 6, 7, 8}

	a := a1[3:5]
	fmt.Println(len(a), cap(a)) // 2 5

	a = a1[3:5:8]
	fmt.Println(len(a), cap(a))
}
```

## Things to watch

- **Capacity boundary violation**: In `a[low:high:max]`, the indices must satisfy `0 <= low <= high <= max <= cap(a)`. Specifying `max > cap(a)` triggers a runtime panic.

## Terms

- **Length**: The number of elements currently stored in a slice.
- **Capacity**: The number of elements from the first element of the slice to the end of the underlying backing array.
- **3-Index Slice**: A slicing expression `slice[low:high:max]` that sets capacity to `max - low`.
