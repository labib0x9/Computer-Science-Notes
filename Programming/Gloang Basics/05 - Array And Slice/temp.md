## How it works

The file contains commented notes and live experiments demonstrating:
1. `s[i:j]` creates a slice of length $j - i$.
2. Slicing beyond `len(s)` but within `cap(s)` successfully extends the slice length without reallocating.
3. Slicing beyond `cap(s)` triggers a runtime panic.
4. When `append` causes `len` to exceed `cap`, Go allocates a new, larger backing array and copies elements over, detaching the new slice from the old backing array.

## Terms

- **Backing Array**: The underlying array in memory where a slice's elements are stored.
- **Slice Header**: A struct in the Go runtime containing a pointer to the backing array, integer `len`, and integer `cap`.
