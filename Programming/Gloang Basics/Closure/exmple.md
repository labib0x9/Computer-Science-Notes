## Overview

This program demonstrates how anonymous functions (closures) in Go capture variables from their enclosing lexical scope by reference. A goroutine modifies a local variable defined in `main()`, and synchronization via `sync.WaitGroup` ensures the mutation is complete before printing.

## Concepts used

- Lexical closure capturing variables by reference
- Concurrency synchronization with `sync.WaitGroup`
- Anonymous goroutine functions (`go func() { ... }()`)

## How it works

1. `sal := "hello"` defines a string in `main()`.
2. `wg.Add(1)` registers one pending concurrent operation.
3. An anonymous function is launched in a goroutine:
   - It captures `sal` from the outer scope by reference.
   - It modifies `sal = "welcome"`.
   - `defer wg.Done()` decrements the wait group counter upon completion.
4. `wg.Wait()` blocks the main goroutine until the child goroutine finishes.
5. `fmt.Println(sal)` outputs `"welcome"`.

## Key excerpt

```go
func main() {
	var wg sync.WaitGroup
	sal := "hello"
	wg.Add(1)

	// closure ....
	go func() {
		defer wg.Done()
		sal = "welcome"
	}()

	wg.Wait()
	fmt.Println(sal)
}
```

## Things to watch

- **Data race without WaitGroup**: If `wg.Wait()` were omitted, reading `sal` in `main` while the goroutine writes to it would cause a data race detectable by `go run -race`.

## Terms

- **Closure**: A function value that references variables from outside its body.
- **sync.WaitGroup**: A synchronization primitive used to wait for a collection of goroutines to finish executing.
