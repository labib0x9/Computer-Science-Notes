## Overview

This program demonstrates the `defer` keyword in Go. Statements prefixed with `defer` have their execution postponed until the surrounding function returns, and multiple deferred calls execute in reverse (LIFO) order.

## Concepts used

- The `defer` keyword
- Last-In-First-Out (LIFO) execution stack
- Immediate evaluation of deferred arguments
- Guaranteed execution on return or panic

## How it works

1. `main()` registers deferred calls:
   - `defer worker1()`
   - `defer worker2()`
2. Normal function execution proceeds: prints standard statements.
3. When `main()` returns, the deferred call stack unwinds in LIFO order:
   - `worker2()` executes first (`"Wroker 2"` in source).
   - `worker1()` executes second (`"Wroker 1"` in source).

## Key excerpt

```go
func worker1() {
	fmt.Println("Wroker 1")
}

func worker2() {
	fmt.Println("Wroker 2")
}

func main() {
	defer worker1()
	defer worker2()
	fmt.Println("Main Done")
}
```

## Things to watch

- **Argument evaluation timing**: Arguments to a deferred function are evaluated immediately when the `defer` statement is encountered, even though the function body does not execute until return time.
- **Typo in output**: The source strings print `"Wroker"` (misspelled).

## Terms

- **defer**: Pushes a function call onto a list that will be executed after the surrounding function completes.
- **LIFO (Last-In, First-Out)**: A stack order where the last item added is the first one processed.
