## Overview

This program demonstrates a functional resource-management pattern in Go where a factory function returns an acquired resource (such as an `*os.File`) together with a parameterless cleanup closure (`func()`), allowing callers to defer cleanup without managing internal teardown details.

## Concepts used

- Returning functions as first-class values (`func()`)
- Encapsulating resource teardown inside closures
- Deferring returned cleanup closures: `defer cleanup()`

## How it works

1. `getFile(path string) (*os.File, func(), error)`:
   - Opens the file with `os.Open(path)`.
   - If opening fails, returns `nil, nil, err`.
   - Constructs a cleanup closure `cleanup := func() { file.Close() }`.
   - Returns the open file pointer and the closure: `return file, cleanup, nil`.
2. In `main`:
   - Calls `file, cleanup, err := getFile("sample.txt")`.
   - Defers the closure: `defer cleanup()`.
   - Reads or processes the file knowing that `cleanup()` will safely execute upon return.

## Key excerpt

```go
func getFile(path string) (*os.File, func(), error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, nil, err
	}

	cleanup := func() {
		file.Close()
	}

	return file, cleanup, nil
}
```

## Expected behavior (from reading the code, not run)

- Opens the specified file and returns the handle and closure.
- The deferred `cleanup()` function closes the file descriptor when `main` completes.

## Things to watch

- **Check for nil closure**: If `getFile` encounters an error, `cleanup` is `nil`. Calling `defer cleanup()` without checking `err != nil` first causes a nil pointer dereference panic. Always verify `if err != nil` before deferring.

## Terms

- **First-Class Functions**: A language feature treating functions as values that can be assigned to variables, passed as arguments, and returned from other functions.
- **Cleanup Closure**: A function capturing a resource that performs required teardown when invoked.
