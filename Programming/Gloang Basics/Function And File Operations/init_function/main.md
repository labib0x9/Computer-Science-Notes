## Overview

This program demonstrates Go's `init()` function mechanism. Any package can declare one or more parameterless, returnless `init()` functions that execute automatically during package initialization before `main()` begins.

## Concepts used

- The special `init()` function
- Package lifecycle and startup order
- Order of execution: package variable initializers, `init()`, then `main()`

## How it works

1. The file defines `func init()`:
   - Prints `"Hello From Init"`.
2. The file defines `func main()`:
   - Prints `"Hello From Main"`.
3. When the Go runtime boots the executable:
   - It initializes package-level variables.
   - It runs all `init()` functions in the package.
   - It invokes `main()`.

## Key excerpt

```go
package main

import "fmt"

func init() {
	fmt.Println("Hello From Init")
}

func main() {
	fmt.Println("Hello From Main")
}
```

## Things to watch

- **Multiple init functions**: A single file or package can have multiple `init()` functions; they execute in source/file order.
- **Cannot be called explicitly**: `init` functions cannot be referenced, assigned, or called explicitly by user code.
- **Side effects**: Overusing `init()` for complex logic can make program flow hard to trace and test; reserve it for registering drivers (e.g. database drivers via blank imports) or validating static configurations.

## Terms

- **init()**: A special parameterless function automatically executed by the Go runtime when a package is initialized.
