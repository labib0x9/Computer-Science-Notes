## Overview

This program demonstrates lexical variable shadowing in Go. It shows how the short declaration operator (`:=`) inside an inner block creates a completely new, distinct variable that shadows an outer variable with the same name without modifying the outer variable's value.

## Concepts used

- Independent variable lifetimes across nested scopes

## How it works

1. In `main()`, `x := 20` initializes an integer in function scope.
2. An explicit inner block `{ ... }` begins:
   - `x := 10` declares a brand new variable named `x` local to that inner block.
   - Modifying or printing `x` inside the block refers exclusively to the inner `x`.
3. When the inner block ends, the inner `x` goes out of scope.
4. Printing `x` in the outer function scope reveals that the original variable retains its value (`20`).

## Key excerpt

```go
func main() {
	x := 20

	{
		x := 10
		fmt.Println("Inner x:", x)
	}

	fmt.Println("Outer x:", x)
}
```

## Things to watch

- **Accidental shadowing**: A very common bug in Go occurs when attempting to reassign an outer variable (like `err` or a result variable) inside an `if` block using `:=` instead of `=` (e.g. `data, err := ...`). The compiler creates a new inner `err` and leaves the outer variable unchanged.
- **shadow linter**: Go developers use tools like `go vet -vettool=$(which shadow)` to detect unintentional shadowing.

## Terms

- **Variable Shadowing**: Declaring a variable in an inner scope with the same name as a variable in an outer scope, making the outer variable temporarily inaccessible.
- **Block Scope**: The lexical region bounded by curly braces `{}` within which declared identifiers exist.
