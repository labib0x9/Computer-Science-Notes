## Overview

This program demonstrates how package-level global variables can be shadowed across multiple nested scopes in Go, comparing global access with function-local and block-local variables sharing the same identifier.

## Concepts used

- Package-level variable declaration (`var x = 100`)
- Function scope shadowing
- Block scope shadowing
- Accessing shadowed globals via helper functions

## How it works

1. `var x = 100` declares a package-level variable.
2. In `main()`:
   - `x := 50` shadows the global `x` with a function-local variable.
   - An inner block `{ x := 10; fmt.Println(x) }` shadows the function-local `x` with an inner variable, printing `10`.
   - Outside the inner block, printing `x` accesses the function-local variable (`50`).
3. Calling `global()` invokes an external function in the same package that was not shadowed, returning the package-level `x` (`100`).

## Key excerpt

```go
var x = 100

func main() {
	x := 50
	{
		x := 10
		fmt.Println(x)
	}
	fmt.Println(x)
	fmt.Println(global())
}

func global() int {
	return x
}
```

## Things to watch

- **Global state clarity**: Shadowing globals can create confusing code where the same identifier refers to different storage locations on consecutive lines. Use distinct variable names.

## Terms

- **Package Scope**: Identifiers declared outside functions that are visible throughout all files in the same package.
