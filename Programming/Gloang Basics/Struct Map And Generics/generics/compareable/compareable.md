## Overview

This program demonstrates the `comparable` constraint in Go generics. It shows how restricting type parameters with `comparable` enables equality operators (`==`, `!=`) and allows types to serve as generic map keys.

## How it works

1. `indexOf[T comparable](arr []T, target T) int`:
   - Because `T` is constrained by `comparable`, the compiler allows `v == target`.
   - Returns the matching index or `-1` if not found.
2. `Keys[K comparable, V any](mp map[K]V) []K`:
   - In Go, map keys must be comparable.
   - Constraining `K` to `comparable` allows `mp map[K]V`.
   - Iterates through `mp`, appends keys to a slice `[]K`, and returns it.

## Key excerpt

```go
func indexOf[T comparable](arr []T, target T) int {
	for i, v := range arr {
		if v == target {
			return i
		}
	}
	return -1
}

func Keys[K comparable, V any](mp map[K]V) []K {
	var keys []K
	for k := range mp {
		keys = append(keys, k)
	}
	return keys
}
```

## Expected behavior (from reading the code, not run)

## Things to watch

- **Non-comparable types**: Types like slices, maps, and functions do not implement `comparable`. Passing a slice of slices to `indexOf` fails compilation.
- **Spelling**: The folder and filename use `compareable` (with an extra 'e').

## Terms

- **comparable**: A built-in interface satisfied by any type whose values can be compared using `==` and `!=`.
