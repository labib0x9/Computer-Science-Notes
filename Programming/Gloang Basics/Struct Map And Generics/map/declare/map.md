## Concepts used

- Nil map declaration (`var mp1 map[string]int`)
- Initializing maps with `make(map[K]V)`
- Map literal initialization
- Key existence verification via comma-ok (`val, ok := mp[key]`)
- Key deletion with `delete(mp, key)`

## How it works

1. `var mp1 map[string]int`: Creates a nil map. `mp1 == nil` is `true`. Reading from `mp1` returns zero values safely, but writing to it panics.
2. `mp2 := make(map[string]int)`: Allocates an initialized empty map. `mp2 == nil` is `false`. Safe for writes.
3. Comma-ok lookup:
   - `val, ok := mp["banana"]`: If `"banana"` exists, `ok` is `true` and `val` holds the value.
   - If missing, `ok` is `false` and `val` is 0.
4. `delete(mp, "banana")`: Removes the key from the map.

## Key excerpt

```go
func main() {
	var mp1 map[string]int	// nil map
	fmt.Println(mp1 == nil)

	mp2 := make(map[string]int)	// empty map
	fmt.Println(mp2 == nil)

	mp2["apple"] = 5
	val, ok := mp2["banana"]
	fmt.Println(val, ok)
```

## Things to watch

- **Zero value ambiguity without comma-ok**: Accessing a missing key returns the value type's zero value (0 for `int`). The comma-ok idiom is necessary to distinguish between a key holding the value 0 and a key that does not exist.

## Terms

- **Map**: An unordered collection of key-value pairs implemented as a hash table in Go.
- **Comma-OK Idiom**: A two-value assignment syntax used to test if a key is present in a map or a type assertion succeeded.
