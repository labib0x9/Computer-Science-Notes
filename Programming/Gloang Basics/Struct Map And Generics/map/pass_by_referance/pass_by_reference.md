## Overview

This program demonstrates that Go maps have reference semantics when passed into functions. It also explains why Go compilers forbid taking the memory address of a map element (`&mp[key]`).

## How it works

1. In `Pass()`:
   - `mp := make(map[string]int)` initializes a map.
   - It calls `function(mp)`. Inside `function`, keys are added to `mp`.
   - When control returns to `Pass()`, `len(mp)` reflects the new entries because maps are internally pointers to runtime hash tables (`*runtime.hmap`).
2. Map element addresses:
   - Attempting `&mp["STR"]` fails with a compile error: `cannot take the address of mp["STR"]`.
   - Because Go maps dynamically grow and rehash buckets, bucket entries move in memory; exposing pointers to map elements would cause dangling pointers.

## Things to watch

- **Unaddressable map elements**: If you store structs in a map (`map[string]MyStruct`), you cannot modify fields in-place via `mp["key"].Field = 1`. You must either reassign the entire struct or store pointers to structs (`map[string]*MyStruct`).
- **Spelling**: The folder name is spelled `pass_by_referance` (with an 'a').

## Terms

- **Unaddressable Value**: A value whose memory location cannot be obtained using the address-of operator `&`.
- **hmap**: The internal Go runtime struct that represents a map.
