## Overview

This program demonstrates the Builder design pattern in Go combined with deferred error accumulation. Rather than checking validation errors on every chained setter call, the builder accumulates validation errors internally and returns them during the final `Build()` step.

## How it works

1. `UserBuilder` struct holds staging fields (`Username`, `Email`) and an internal `Err error`.
2. Chained setter methods:
   - `SetUsername(username string) *UserBuilder`: If `username == ""`, sets `b.Err = errors.New(...)`. Returns `b`.
   - `SetEmail(email string) *UserBuilder`: If `email == ""`, sets `b.Err = errors.New(...)`. Returns `b`.
3. `Build() (*User, error)`:
   - If `b.Err != nil`, returns `nil, b.Err`.
   - Otherwise, constructs and returns a fully initialized `*User`.

## Key excerpt

```go
type UserBuilder struct {
	Username string
	Email    string
	Err      error
}

func (b *UserBuilder) SetUsername(u string) *UserBuilder {
	if b.Err != nil {
		return b
	}
	if u == "" {
		b.Err = errors.New("username cannot be empty")
		return b
	}
	b.Username = u
	return b
}
```

## Expected behavior (from reading the code, not run)

- Valid chained configuration produces a valid `*User`.
- Invalid configuration captures the error and returns it when `Build()` is called.

## Things to watch

- **Preserving first error**: The builder checks `if b.Err != nil { return b }` at the start of each setter so that subsequent setters do not overwrite the initial validation error.

## Terms

- **Builder Pattern**: A creational design pattern that allows constructing complex objects step by step.
- **Error Accumulation**: Postponing error reporting until the end of a multi-step operation.
