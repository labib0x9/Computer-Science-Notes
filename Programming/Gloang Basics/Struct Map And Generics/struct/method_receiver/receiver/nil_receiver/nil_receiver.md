## Overview

This program demonstrates a unique feature of Go: methods with pointer receivers can be safely invoked on `nil` pointers. It demonstrates this pattern by implementing an immutable recursive binary search tree where inserting into a `nil` node allocates a new node cleanly.

## How it works

1. Struct `IntTree` contains `val int` and pointers `left, right *IntTree`.
2. Method `(it *IntTree) Insert(val int) *IntTree`:
   - Checks `if it == nil`: if called on a `nil` pointer, returns `&IntTree{val: val}` directly without panicking.
   - If `val < it.val`, recursively updates `it.left = it.left.Insert(val)`.
   - Otherwise, updates `it.right = it.right.Insert(val)`.
   - Returns `it`.
3. Callers can initialize trees starting from `nil`:
   ```go
   var tree *IntTree
   tree = tree.Insert(5)
   tree = tree.Insert(3)
   ```

## Key excerpt

```go
type IntTree struct {
	val int
	left, right *IntTree
}

func (it *IntTree) Insert(val int) *IntTree {
	if it == nil {
		return &IntTree{val: val}
	}
	if it.val < val {
		it.right = it.right.Insert(val)
	} else {
		it.left = it.left.Insert(val)
	}
	return it
}
```

## Things to watch

- **Nil dereference without check**: If a method receiver is `nil` and the method attempts to access a field (e.g. `it.val`) before checking `it == nil`, Go panics with a runtime nil pointer dereference. Always perform nil checks before field access in methods intended to support nil receivers.

## Terms

- **Nil Receiver**: A method invocation where the receiver pointer argument is `nil`.
