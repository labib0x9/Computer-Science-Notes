## Overview

This program demonstrates the fundamental distinction between value receivers and pointer receivers in Go. It shows that value receiver methods receive a copy of the struct and cannot mutate the caller's state, whereas pointer receivers operate directly on the original struct in memory.

## Concepts used

- Value receivers: `func (u User) Method()`
- Pointer receivers: `func (u *User) Method()`
- Mutation persistence across method calls
- Automatic address-taking and dereferencing by the Go compiler

## How it works

The code defines struct `User`:
1. Value receiver method `(u User) SetAgeValue(age int)`:
   - Receives a shallow copy of `User`.
   - Modifying `u.Age = age` alters only the local copy; the caller's struct remains unchanged.
2. Pointer receiver method `(u *User) SetAgePointer(age int)`:
   - Receives the memory address `*User`.
   - Modifying `u.Age = age` persists to the original struct.
3. In `methodReciever()`:
   - Calls both methods and prints values, proving that only pointer receivers mutate caller state.

## Key excerpt

```go
type User struct {
	Name string
	Age  int
}

func (u User) setAgeCopy(age int) {
	u.Age = age
}
```

## Things to watch

- **Receiver consistency**: As a general rule in Go, if any method on a struct requires a pointer receiver for mutation, all methods on that struct should typically use pointer receivers for consistency.
- **Spelling**: The filename and function use `reciever.go` / `methodReciever` (spelled with 'ie' instead of 'ei').

## Terms

- **Value Receiver**: A receiver that receives a copy of the value on each method invocation.
- **Pointer Receiver**: A receiver that receives a pointer to the value, allowing mutations and avoiding copy overhead for large structs.
