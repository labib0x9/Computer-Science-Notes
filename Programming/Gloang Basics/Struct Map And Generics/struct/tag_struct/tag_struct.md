This source file illustrates advanced JSON struct tag options in Go. It demonstrates field renaming, omitting empty fields (`omitempty`), coercing numbers to JSON strings (`string`), and completely excluding sensitive fields (`-`) from serialization.

## Concepts used

- JSON struct tags syntax (`json:"key,options"`)
- Excluding empty values with `omitempty`
- Number-to-string coercion with `,string`
- Field exclusion using the dash `-` directive

## How it works

The `User` struct declares four tagged fields:
1. `Username string json:"username"`: Renames the field key in JSON to lowercase `"username"`.
2. `Email string json:"email,omitempty"`: Renames key to `"email"`; if `Email` is empty (`""`), the key is omitted entirely from marshaled JSON output.
3. `Id int json:"id,string"`: Serializes the integer `Id` as a JSON string (e.g. `"id": "123"` instead of `"id": 123`), useful for compatibility with JavaScript systems where 64-bit integers lose precision.
4. `Password string json:"-"`: Completely excludes the `Password` field from both serialization and deserialization, preventing credential leakage.

## Things to watch

- **omitempty on zero-value structs**: In Go versions prior to 1.24, `omitempty` on a nested struct field does not omit the field unless it is a pointer (`*Struct`); a zero-value struct is not considered empty.
- **Literal dash as key**: If a field needs to literally be named `"-"` in JSON rather than excluded, specify `json:"-,"`.

## Terms

- **omitempty**: Struct tag option that instructs encoders to omit the field if it holds its zero value.
- **Field Exclusion (`-`)**: Struct tag directive that hides a field from serialization.
