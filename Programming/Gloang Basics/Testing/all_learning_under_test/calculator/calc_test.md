## How it works

The test function `TestAdd(t *testing.T)`:
1. Calls `t.Parallel()`, signaling the test runner that this test can safely execute in parallel with other parallel tests.
2. Performs a single assert: calls `Add(4, 6)` and verifies `got == want`.
3. Defines a slice of test cases:
   ```go

       a, b float64
   ```

4. Iterates over the test cases, invokes `Add(tc.a, tc.b)`, and reports failures via `t.Errorf`.

## Key excerpt

```go
func TestAdd(t *testing.T) {
	t.Parallel() // Runs this code parallel with other
	var want float64 = 10
	got := Add(4, 6)
```

## Things to watch

- **t.Parallel scoping**: When using `t.Parallel()` inside subtests within a range loop, ensure loop variables are re-bound in Go versions prior to 1.22 to avoid data race closures.

## Terms

- **t.Parallel**: Marks a test function as capable of running in parallel with other parallel tests.
- **Table-Driven Test**: A testing pattern where test inputs and expected outputs are organized in a table (slice of structs) and processed by a single test loop.
