## Overview

This program demonstrates how to configure and handle publisher confirms with RabbitMQ using the `github.com/rabbitmq/amqp091-go` driver in Go. Publisher confirms ensure that messages sent to an exchange have been durably processed or rejected by the broker before proceeding.

## Source

[confirm_publish.go](https://github.com/labib0x9/Programming-Notes/blob/main/Programming/Golang%20Backend/AMQP-RabbitMQ/confirm_publish.go)

## Concepts used

- RabbitMQ publisher confirms via `ch.Confirm(false)`
- Asynchronous confirmation listener using `ch.NotifyPublish`
- Direct exchange declaration and durable queue binding
- Basic message publishing with `ch.PublishWithContext`

## How it works

The program connects to RabbitMQ at `localhost:5672` and opens a channel:
1. `declareExchange` and `declareQueue` ensure a direct exchange named `logs` and a durable queue named `info-logs` exist and are bound by routing key `logs.info`.
2. It puts the channel into confirmation mode by calling `ch.Confirm(false)`.
3. It registers a buffered confirmation channel via `confirms := ch.NotifyPublish(make(chan amq.Confirmation, 1))`.
4. A background goroutine reads from `confirms` in a range loop, inspecting `c.Ack` to verify if each delivery tag was acknowledged (`published!!!`) or negative-acknowledged (`not published ;__) !`).
5. `publish` sends messages to the exchange using `PublishWithContext`.

In `main`, multiple messages are published with varying routing keys while the background listener reports broker ACKs.

## Key excerpt

```go
	// confirming mode
	if err := ch.Confirm(false); err != nil {
		panic(err)
	}

	// publish notifications are comming here
	confirms := ch.NotifyPublish(make(chan amq.Confirmation, 1))

	go func() {
		fmt.Println("I AM INSIDE THE CONFIRMATION GOROUTINE.")
		for c := range confirms {
			if c.Ack {
				fmt.Println(c.DeliveryTag, "published!!!")
			} else {
				fmt.Println(c.DeliveryTag, "not published ;__) !")
			}
		}
	}()
```

## Things to watch

- **Buffer sizing for confirms**: `make(chan amq.Confirmation, 1)` has capacity 1; for high-throughput producers, a larger buffer or batch acknowledgment strategy prevents producer stalls.
- **Unroutable messages**: A message successfully confirmed by the broker might still be discarded if no queue is bound to its routing key unless the `mandatory` flag is set.

## Terms

- **Publisher Confirms**: An AMQP extension that notifies producers when the broker has processed a published message.
- **DeliveryTag**: A monotonically increasing integer assigned to each message on a channel.
