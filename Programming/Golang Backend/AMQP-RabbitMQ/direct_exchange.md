## Overview

This program demonstrates how to configure and use a RabbitMQ direct exchange in Go using `amqp091-go`. In a direct exchange, messages are delivered to queues whose binding key matches the message routing key exactly.

## How it works

The code connects to RabbitMQ and configures routing infrastructure:
1. `declareQueue(ch, exchange, typee, queue, route)` declares the exchange with `ch.ExchangeDeclare` using type `direct`.
2. It declares a durable queue (`queue = true`) using `ch.QueueDeclare`.
3. It binds the queue to the exchange with `ch.QueueBind` matching the specified route.
4. Two queues are declared: `info-logs` (bound to `logs.info`) and `error-logs` (bound to `logs.error`).
5. `consume` starts a consumer goroutine that pulls delivery items from the queue and prints their body to stdout.
6. `publish` emits messages tagged with `logs.info` or `logs.error`.

Messages with routing key `logs.info` go exclusively to `info-logs`, while messages with `logs.error` go to `error-logs`.

## Key excerpt

```go
func declareQueue(ch *amq.Channel, exchange, typee string, queue, route string) error {
	if err := ch.ExchangeDeclare(exchange, typee, false, false, false, false, nil); err != nil {
		return err
	}

	q, err := ch.QueueDeclare(queue, true, false, false, false, nil)
	if err != nil {
		return err
	}

	if err := ch.QueueBind(q.Name, route, exchange, false, nil); err != nil {
		return err
	}
	return nil
}
```

## Things to watch

- **Auto-ack setting**: `ch.ConsumeWithContext` sets `autoAck = true`, which means the broker removes messages immediately upon delivery, without waiting for processing confirmation.
- **Queue durability mismatch**: Declaring an existing queue with different durability settings causes RabbitMQ channel exceptions.

## Terms

- **Direct Exchange**: An exchange algorithm that routes messages based on exact equality between routing key and binding key.
- **QueueBind**: AMQP operation linking a queue to an exchange.
