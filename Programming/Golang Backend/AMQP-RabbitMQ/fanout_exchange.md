## Overview

This program demonstrates how to broadcast messages to multiple independent queues using a RabbitMQ fanout exchange. In a fanout exchange, routing keys are completely ignored and messages are replicated to all bound queues.

## Concepts used

- Fanout exchange broadcast pattern
- Binding multiple queues to a single exchange without routing keys
- Concurrent consumer goroutines processing mirrored message streams

## How it works

The program establishes an AMQP connection and channel:
1. `declareExchange` sets up a fanout exchange named `logs`.
2. It declares two separate durable queues: `info-logs` and `error-logs`.
3. Both queues are bound to the `logs` exchange with empty or dummy routing keys.
4. Two consumer goroutines (`consume`) listen to `info-logs` and `error-logs`.
5. `publish` sends messages to the exchange.

Because the exchange is `fanout`, every published message is copied into both `info-logs` and `error-logs`, allowing both consumer goroutines to process identical payloads.

## Things to watch

- **Ignored routing keys**: Any routing key specified in `PublishWithContext` is ignored by the fanout exchange.
- **Unbound messages dropped**: If a message is published before any queues are bound to the fanout exchange, the message is discarded by the broker.

## Terms

- **Fanout Exchange**: An exchange that copies and delivers messages to all queues bound to it regardless of routing keys.
- **Pub/Sub**: Publish/Subscribe pattern where publishers send messages to multiple subscribers without knowing who they are.
