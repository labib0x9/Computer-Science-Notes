## How it works

The snippet defines a single helper function `consume`:
1. It opens an AMQP channel from the provided connection `conn`.
2. A 20-second timeout context is created to govern consumer lifetime.
3. `ch.Qos(10, 0, false)` sets the prefetch count to 10:
   - `prefetchCount = 10`: The broker will not deliver more than 10 unacknowledged messages to this consumer at once.
   - `prefetchSize = 0`: No byte-size limit is enforced.
   - `global = false`: The setting applies specifically to this consumer rather than sharing the limit across all consumers on the channel.
4. `ch.ConsumeWithContext` starts consuming from the queue with `autoAck = true`.
5. A `select` loop prints message bodies until the context timeout triggers.

## Things to watch

- **Incomplete file**: The file contains only `func consume` without `package` or `import` headers; it cannot be compiled standalone.
- **QoS with autoAck**: Setting `ch.Qos` has no throttling effect if `autoAck` is set to `true`, because the broker treats messages as acknowledged immediately upon sending them. For `Qos` to restrict flow, `autoAck` must be `false` and messages must be acknowledged manually via `Delivery.Ack`.

## Terms

- **Prefetch Count**: The maximum number of unacknowledged messages RabbitMQ will send to a consumer before pausing delivery.
- **QoS (Quality of Service)**: The AMQP method used to configure prefetch limits.
