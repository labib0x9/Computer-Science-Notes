## Overview

This program demonstrates the fundamental RabbitMQ producer and consumer pattern in Go. It provisions an exchange and queue, launches a consumer goroutine to read deliveries, and publishes sample messages over an AMQP channel.

## Concepts used

- Basic exchange declaration (`ch.ExchangeDeclare`)
- Queue declaration and binding (`ch.QueueDeclare`, `ch.QueueBind`)
- Message publishing with `ch.PublishWithContext`
- Asynchronous consuming via `ch.ConsumeWithContext`

## How it works

The code connects to RabbitMQ at `amqp://guest:guest@localhost:5672`:
1. `declareQueue` creates a direct exchange named `my-exchange` and a queue named `my-queue`, binding them via routing key `my-key`.
2. A consumer goroutine is spawned using `ch.ConsumeWithContext`. It reads from the delivery channel `msgs` and prints the payload of each incoming message to stdout.
3. In the main goroutine, a for loop iterates 5 times, publishing messages (`Msg 0`, `Msg 1`, etc.) to `my-exchange` using routing key `my-key`.
4. A brief sleep allows the consumer goroutine time to process incoming deliveries before the connection terminates.

## Key excerpt

```go
	exchangeName := "my-exchange"
	exchangeType := "direct"
	routingKey := "my-key"
	queueName := "my-queue"
	if err := declareQueue(ch, exchangeName, exchangeType, queueName, routingKey); err != nil {
		panic(err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	msgs, err := ch.ConsumeWithContext(ctx, queueName, "consumer-1", true, false, false, false, nil)
	if err != nil {
		panic(err)
	}

	go func() {
		for m := range msgs {
			fmt.Println("CONSUMED:", string(m.Body))
		}
	}()
```

## Things to watch

- **Shared channel concurrency**: While consuming and publishing on the same channel works in simple demos, the AMQP 0.9.1 Go driver recommends dedicating separate channels for publishing and consuming in production systems.
- **AutoAck**: Messages are automatically acknowledged upon receipt; unhandled panics inside consumer loops can cause lost messages.

## Terms

- **Producer**: An application component that creates and publishes messages to an exchange.
- **Consumer**: A component that subscribes to a queue and processes arriving messages.
