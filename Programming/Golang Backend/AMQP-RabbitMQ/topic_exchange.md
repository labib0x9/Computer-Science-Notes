## Overview

This program demonstrates pattern-based message routing using a RabbitMQ topic exchange. It shows how consumers can bind queues using wildcard patterns (`*` for exactly one word and `#` for zero or more words) to selectively filter message streams.

## How it works

The program establishes an AMQP connection and channel:
1. `declareExchange` provisions a topic exchange named `logs`.
2. It declares multiple queues bound with different routing patterns:
   - `info-logs` bound to `logs.info.*` (matches `logs.info.user`, `logs.info.order`, etc.)
   - `all-logs` bound to `logs.#` (matches any log hierarchy)
3. Consumer goroutines are attached to each queue.
4. `publish` sends messages with dot-delimited routing keys like `logs.info.user` or `logs.error.payment`.

The topic exchange evaluates routing patterns dynamically: `logs.info.user` routes to both queues, while `logs.error.payment` routes only to `all-logs`.

## Things to watch

- **Wildcard definitions**: In RabbitMQ topic exchanges, `*` matches exactly one word delimited by dots; `#` matches zero or more words.
- **Routing performance**: Topic exchanges perform pattern matching on routing strings and are slightly more CPU-intensive than direct exchanges.

## Terms

- **Topic Exchange**: An AMQP exchange routing messages based on pattern matching between routing keys and binding patterns.
- **Routing Key**: A dot-delimited string (e.g. `kern.critical`) attached to a published message.
