## Overview

This program demonstrates server-side validation of Cloudflare Turnstile challenge tokens. It exposes an HTTP POST login endpoint that verifies Turnstile tokens submitted by frontend clients against Cloudflare's verification API before allowing access.

## Concepts used

- Outbound HTTP POST form submissions with `http.PostForm`
- URL encoding of form parameters with `url.Values`
- IP address extraction using `net.SplitHostPort`
- CORS middleware wrapper for POST and OPTIONS requests
- JSON request decoding and response encoding

## How it works

The program defines structures `loginReq` (holding credentials and `TurnstileToken`) and `turnstileResp` (capturing Cloudflare's validation outcome).

When a client hits `/login`:
1. `corsMiddleware` handles CORS preflight and injects headers.
2. `loginHandler` parses incoming JSON into `loginReq`.
3. It extracts the remote client IP address using `net.SplitHostPort(r.RemoteAddr)`.
4. It calls `verifyTurnstile(req.TurnstileToken, ip)`. Inside `verifyTurnstile`:
   - It builds form values containing the Turnstile secret key, token response, and client IP.
   - It posts the form to `https://challenges.cloudflare.com/turnstile/v0/siteverify`.
   - It decodes the JSON response and returns `result.Success`.
5. If verification fails or produces an error, `loginHandler` responds with HTTP 403 Forbidden. Otherwise, it writes `{"status": "ok"}` with HTTP 200.

```go
func verifyTurnstile(token, remoteIP string) (bool, error) {
	form := url.Values{}
	// -- SECRET KEY -- //
	// form.Set("secret", "1x0000000000000000000000000000000AA")
	form.Set("secret", "0x4AA**********************Vg")
	form.Set("response", token)
	form.Set("remoteip", remoteIP)

	resp, err := http.PostForm(
		"https://challenges.cloudflare.com/turnstile/v0/siteverify",
		form,
	)
	if err != nil {
		return false, err
	}
	defer resp.Body.Close()

	var result turnstileResp
	if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
		return false, err
	}
	return result.Success, nil
}
```

## Expected behavior (from reading the code, not run)

- Sending an `OPTIONS` request to `/login` returns CORS headers.
- Sending a `POST` request with a valid Turnstile token causes `verifyTurnstile` to query Cloudflare and, if valid, returns HTTP 200 `{"status":"ok"}`.
- Submitting an invalid or dummy token results in HTTP 403 Forbidden with `captcha verification failed`.

## Things to watch

- **Secret key configuration**: The secret key in `verifyTurnstile` is masked in source code (`0x4AA...Vg`). For working deployments, pass active Cloudflare Turnstile secret keys via environment variables.
- **Client IP behind reverse proxies**: `r.RemoteAddr` contains the immediate TCP peer address. Behind proxies or tunnels (like `cloudflared`), check `CF-Connecting-IP` or `X-Forwarded-For`.

## Terms

- **Cloudflare Turnstile**: A user-friendly, privacy-focused alternative to traditional visual CAPTCHA services.
- **Siteverify API**: Cloudflare's backend endpoint for confirming token validity with a shared secret key.
