## Overview

This program demonstrates why a single `*pgx.Conn` cannot be shared across multiple concurrent goroutines in Go. It illustrates how concurrent queries on a single raw connection trigger PostgreSQL protocol collisions (`conn busy`), demonstrating the need for connection pools like `pgxpool`.

## Concepts used

- Single TCP connection concurrency constraints in PostgreSQL wire protocol
- The `conn busy` error condition in pgx
- Goroutine synchronization using `sync.WaitGroup`
- The architectural distinction between `*pgx.Conn` and `*pgxpool.Pool`

## How it works

The code creates a single PostgreSQL connection:
1. `pgx.Connect` opens a single underlying TCP connection `conn`.
2. A `sync.WaitGroup` spawns 4 concurrent goroutines.
3. Every goroutine attempts to execute `conn.QueryRow("select * from urls where id=$1", id)` on the shared `conn`.
4. Because the PostgreSQL frontend/backend protocol is half-duplex and expects sequential message flows per connection, pgx guards the connection state.
5. The first goroutine locks the wire protocol while subsequent goroutines immediately fail with `conn busy`.

## Key excerpt

```go
	conn, err := pgx.Connect(context.Background(), pgURL) // 1-TCP connection.
	if err != nil {
		panic(err)
	}
	defer conn.Close(context.Background())

	var wg sync.WaitGroup
	for i := range 4 {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			query := "select * from urls where id=$1"
			row := conn.QueryRow(context.Background(), query, id)
			var found Url
			if err := row.Scan(&found.Id, &found.Url); err != nil {
				fmt.Println("GOROUTINE=", id, "ERRor=", err)
			} else {
				fmt.Println("GOROUTINE=", id, "FOUND ID=", found.Id, "URL=", found.Url)
			}
		}(i)
	}
	wg.Wait()
```

## Expected behavior (from reading the code, not run)

- One goroutine succeeds in querying the database and prints `FOUND ID= ...`.
- The other concurrent goroutines fail with errors logging `GOROUTINE= <n> ERRor= conn busy`.

## Things to watch

- **Design lesson**: A `*pgx.Conn` must never be accessed concurrently. For multi-threaded or HTTP web server environments, always use `*pgxpool.Pool`.
- **Hardcoded credentials**: The connection string contains hardcoded credentials (`short:secret`).

## Terms

- **Protocol Collision**: An error that occurs when concurrent commands are sent over a single half-duplex network protocol connection before the previous response has completed.
- **Half-duplex**: A communication channel where transmission occurs in only one direction at a time.
