This program demonstrates how to query single and multiple rows in PostgreSQL using `pgx v5`. It covers handling missing records via `pgx.ErrNoRows`, scanning column data into structs, and iterating over multiple rows.

## How it works

The code connects to PostgreSQL using `pgx.Connect`:
1. It queries a nonexistent ID (`10000`) using `conn.QueryRow`.
2. When scanning into `foundURL`, `row.Scan` returns `pgx.ErrNoRows`. The code checks `errors.Is(err, pgx.ErrNoRows)` and prints `No rows returned`.
3. It performs a multi-row query `SELECT id, url FROM urls`.
4. It iterates over the result set with `rows.Next()`, extracts values via `rows.Scan`, and accumulates results into a slice.

## Key excerpt

```go
	query := "select * from urls where id=$1"
	row := conn.QueryRow(context.Background(), query, 10000) // 10000 not in the table

	// Not found error
	var foundURL Url
	if err := row.Scan(&foundURL); err != nil {
		if errors.Is(err, pgx.ErrNoRows) {
			println("No rows returned")
		} else {
			panic(err)
		}
	} else {
		fmt.Println("Found=", foundURL)
	}
```

## Things to watch

- **ErrNoRows timing**: `conn.QueryRow` does not return an error itself; the error is deferred and returned when `row.Scan` is called.
- **Resource closure**: `rows.Close()` should be deferred after `conn.Query` to ensure the connection releases the query state even if iteration terminates early.
- **Hardcoded credentials**: The connection string contains hardcoded credentials (`short:secret`).

## Terms

- **pgx.ErrNoRows**: Sentinel error returned by `Scan` on a `Row` when the query returned no matching rows.
- **Sentinel error**: A predefined package-level error constant used with `errors.Is` for comparison.
