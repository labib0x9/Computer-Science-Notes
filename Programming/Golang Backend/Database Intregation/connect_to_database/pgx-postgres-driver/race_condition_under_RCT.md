## Overview

This program demonstrates race conditions that occur under PostgreSQL's default Read Committed Transaction (RCT) isolation level. It shows how concurrent transactions performing read-modify-write cycles can overwrite each other's changes unless row-level locks (`SELECT FOR UPDATE`) or stricter isolation levels are applied.

## How it works

The program connects to PostgreSQL via `pgxpool.Pool`:
1. `txRC(pool, id, serial)` begins a transaction:
   - Reads a record: `SELECT * FROM urls WHERE id=$1`.
   - Validates the URL value.
   - Updates the URL with a new serialized string: `UPDATE urls SET url=$2 WHERE id=$1`.
   - Commits the transaction with `tx.Commit`.
2. In `main`, multiple concurrent worker goroutines invoke `txRC` on the exact same row ID simultaneously.
3. Under Read Committed isolation, each transaction sees committed state at the moment its query executes. Two concurrent transactions can both read the original row before either commits an update, leading to lost updates or unexpected states.

func txRC(pool *pgxpool.Pool, id int, serial int) (ans any, err error) {

	tx, err := pool.Begin(context.Background())
	if err != nil {
		return nil, err
	}
	defer tx.Rollback(context.Background()) // safe - after commit rollback does nothing

	query := "select * from urls where id=$1" // row - lock here to prevent...
	row := tx.QueryRow(context.Background(), query, id)
	var found Url
	if err := row.Scan(&found.Id, &found.Url); err != nil {
		return nil, err
	}

	if found.Url != "https://labib0x0hunter.netlify.app/#projects" {
		return nil, errors.New("not the url i want...")
	}

	longUrl := "https://labib0x0hunter.netlify.app/no_need_to_know_whoami_" + strconv.Itoa(serial)
	query = "update urls set url=$2 where id=$1 returning id, url"
	updatedRow := tx.QueryRow(context.Background(), query, id, longUrl)
	var updatedUrl Url
	if err := updatedRow.Scan(&updatedUrl.Id, &updatedUrl.Url); err != nil {
		return nil, err
	}

	if err := tx.Commit(context.Background()); err != nil {
		return nil, err
	}
	return updatedUrl, nil
}

## Expected behavior (from reading the code, not run)

- One transaction reads the initial URL, modifies it, and commits.
- Subsequent or concurrent transactions that expect the original URL fail with `not the url i want...` once an update commits, or overwrite state if interleaving occurs before commit.

## Things to watch

- **Fixing the race condition**: To avoid race conditions in read-modify-write patterns, either use row locks (`SELECT ... FOR UPDATE`) or elevate transaction isolation to `pgx.RepeatableRead` / `pgx.Serializable`.
- **Hardcoded credentials**: The connection string contains hardcoded credentials (`short:secret`).

## Terms

- **Read Committed**: Default SQL isolation level guaranteeing that transactions only read data committed before the query began.
- **FOR UPDATE**: SQL clause that locks selected rows against concurrent modifications until transaction commit.
