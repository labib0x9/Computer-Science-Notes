## Overview

This program demonstrates reading external SQL migration files (`.sql`) from the filesystem and executing them sequentially against a PostgreSQL database using `github.com/jmoiron/sqlx` and `github.com/lib/pq`.

## How it works

The code implements a migration runner helper `TableOP`:
1. `TableOP(dbConn, path)` reads the SQL file specified by `path` into memory using `os.ReadFile`.
2. It executes the raw SQL text against PostgreSQL via `dbConn.Exec(string(query))`.
3. In `main`:
   - It formats a PostgreSQL connection string for database `tempdb1`.
   - It connects via `sqlx.Connect("postgres", dbSource)`.
   - It executes three migration teardown scripts sequentially: `00001_create_users_table.down.sql`, `00002_create_email_verification_table.down.sql`, and `00003_create_labs_table.down.sql`.

func TableOP(dbConn *sqlx.DB, path string) {
	query, err := os.ReadFile(path)
	if err != nil {
		panic(err)
	}

## Things to watch

- **Missing migration files**: The code references relative paths like `./migrations/00001_create_users_table.down.sql`. If executed outside the project root or if migration files do not exist, the program panics immediately.
- **Hardcoded credentials**: Credentials `user := "tempuser1"` and `pass := "<REDACTED>"` are embedded in source code.
- **Transaction safety**: `TableOP` executes outside an explicit transaction; if a script fails halfway through, preceding commands remain applied. Wrapping scripts in transactions ensures atomic migrations.
