## Overview

This program demonstrates how to attach request-scoped metadata (such as correlation or request IDs) to an `http.Request` context using `context.WithValue`, and retrieve it downstream in logging utilities.

## How it works

The code defines an unexported key type `requestContextKey` and a value container `requestContextValue`:
1. `addRequestID(r *http.Request, requestID string)` constructs a new child context using `context.WithValue(r.Context(), requestContextKey{}, c)`. It returns a shallow copy of the request with the updated context using `r.WithContext(ctx)`.
2. In `apiHandler`:
   - It calls `r = addRequestID(r, "1234")` to inject a sample request ID.
   - It invokes `loggerHelper(r)` and writes `API HANDLER` to the response.
3. In `loggerHelper`:
   - It extracts the value using `r.Context().Value(requestContextKey{})`.
   - If present, it logs the request method, path, and `request_id` via `slog.Info`.

## Key excerpt

```go
type requestContextKey struct{}
type requestContextValue struct {
	requestId string
}

func addRequestID(r *http.Request, requestID string) *http.Request {
	c := requestContextValue{
		requestId: requestID,
	}

	currentCtx := r.Context()
	newCtx := context.WithValue(currentCtx, requestContextKey{}, c)
	return r.WithContext(newCtx)
}
```

## Things to watch

- **Context immutability**: `r.WithContext(ctx)` returns a shallow copy of `http.Request`. You must reassign `r = addRequestID(r, ...)` or pass the new request pointer downstream.
- **Middleware placement**: In production apps, request ID injection is typically implemented in an outer middleware rather than inside individual handler functions.

## Terms

- **context.WithValue**: Attaches a key-value pair to a context; keys should be unexported custom types to avoid package namespace collisions.
- **Correlation ID**: A unique identifier passed through distributed services to trace a single user request across log streams.
