## Overview

This program demonstrates how to parse multiple consecutive, un-delimited JSON objects streamed in a single HTTP request body. It contrasts `json.NewDecoder` streaming with standard `json.Unmarshal`.

## How it works

The program defines three sample handlers:
- `apiHandler`: Uses `json.NewDecoder(r.Body)` in a `for decoder.More()` loop. Each iteration decodes the next adjacent JSON object into `ReqType` until EOF, allowing requests like `{"ip": "1.1.1.1"} {"ip": "2.2.2.2"}` to be parsed completely.
- `api2Handler`: Demonstrates calling `decoder.Decode(&req)` once followed by `io.ReadAll(decoder.Buffered())` to detect leftover trailing data.
- `api3Handler`: Reads the entire body with `io.ReadAll` and calls `json.Unmarshal`, illustrating that `Unmarshal` only decodes the first JSON object and ignores or fails on subsequent text.

## Key excerpt

```go
func apiHandler(w http.ResponseWriter, r *http.Request) {
	defer r.Body.Close()

	decoder := json.NewDecoder(r.Body)

	for decoder.More() {
		var req ReqType
		if err := decoder.Decode(&req); err != nil {
			if errors.Is(err, io.EOF) {
				break
			}
			http.Error(w, err.Error(), http.StatusBadRequest)
			return
		}
		fmt.Printf("Received: %+v\n", req)
	}

	fmt.Fprintf(w, "API HANDLER")
}
```

## Things to watch

- **NDJSON vs Raw Concatenation**: `json.Decoder` handles whitespace-separated or newline-delimited JSON (NDJSON) as well as raw concatenated JSON objects without commas.
- **Request body size limits**: Unbounded stream decoding can lead to denial-of-service vulnerabilities; wrap `r.Body` with `http.MaxBytesReader` to enforce upload limits.

## Terms

- **json.Decoder.More**: Reports whether there is another element in the current array or object being parsed.
- **NDJSON**: Newline Delimited JSON, a standard format for streaming JSON records.
