## Overview

This program demonstrates strict schema enforcement in Go HTTP APIs by configuring `json.Decoder.DisallowUnknownFields`. By default, Go ignores extra JSON keys; enabling this setting causes decoding to fail if clients submit unmapped attributes.

## How it works

The program defines a target struct `logLine` containing only `UserIP` and `Event`.

In `decodeHandler`:
1. It instantiates `decoder := json.NewDecoder(r.Body)`.
2. It calls `decoder.DisallowUnknownFields()`.
3. It executes `decoder.Decode(&line)`.
4. If the JSON payload contains fields not present in `logLine` (such as `user_data`), `Decode` returns an error (e.g. `json: unknown field "user_data"`).
5. The handler catches this error, logs it via `slog.Error`, and returns HTTP 400 with the error description.

## Key excerpt

```go
type logLine struct {
	UserIP string `json:"user_ip"`
	Event  string `json:"event"`
}

func decodeHandler(w http.ResponseWriter, r *http.Request) {
	defer r.Body.Close()

	decoder := json.NewDecoder(r.Body)
	decoder.DisallowUnknownFields()

	var line logLine
	err := decoder.Decode(&line)
	if err != nil {
		slog.Error("decode error", "error", err)
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	w.WriteHeader(http.StatusOK)
}
```

## Things to watch

- **API versioning**: Disallowing unknown fields makes APIs strict against payload changes, which can cause backward compatibility issues if clients send newer fields to older backend versions.
- **Trailing garbage**: Calling `Decode` once decodes the first JSON object but ignores subsequent trailing text unless followed by an EOF check or `decoder.More()`.

## Terms

- **DisallowUnknownFields**: A configuration on `json.Decoder` that returns an error if the input JSON contains keys that do not match destination struct fields.
