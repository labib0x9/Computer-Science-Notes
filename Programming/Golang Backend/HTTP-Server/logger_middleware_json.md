## Overview

This program demonstrates how to replace repetitive manual logging helper calls with clean, composable HTTP middleware in Go using `log/slog`.

## Concepts used

- HTTP handler decorator pattern (`func(http.Handler) http.Handler`)
- Centralized request interception
- Structured JSON logging with `slog.New(slog.NewJSONHandler(...))`
- Separation of concerns between logging and endpoint business logic

## How it works

The code configures `slog` to write JSON to stdout in `init()`.

`loggerMiddleware(h http.Handler) http.Handler`:
1. Returns an `http.HandlerFunc` wrapping the target handler `h`.
2. When a request arrives, it logs `r.Method`, `r.URL.Path`, and `r.RemoteAddr` via `slog.Info`.
3. It calls `h.ServeHTTP(w, r)` to pass execution to the inner handler.

In `main`:
- Handlers `apiHandler` and `nopeHandler` contain pure business logic with no logging calls.
- The router wraps registered handlers: `mux.Handle("/api", loggerMiddleware(http.HandlerFunc(apiHandler)))`.

## Key excerpt

```go
func loggerMiddleware(h http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		slog.Info("request",
			"method", r.Method,
			"path", r.URL.Path,
			"remote_addr", r.RemoteAddr,
		)
		h.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.Handle("/api", loggerMiddleware(http.HandlerFunc(apiHandler)))
	mux.Handle("/nope", loggerMiddleware(http.HandlerFunc(nopeHandler)))
```

## Expected behavior (from reading the code, not run)

- Requests to `/api` or `/nope` emit structured JSON log entries before returning their response strings.
- Eliminates manual logging calls from handler implementations.

## Things to watch

- **Global vs route-specific middleware**: Wrapping individual routes with `mux.Handle(path, loggerMiddleware(...))` can be tedious; wrapping the entire `mux` (e.g. `http.ListenAndServe(":8080", loggerMiddleware(mux))`) applies logging globally across all routes.
