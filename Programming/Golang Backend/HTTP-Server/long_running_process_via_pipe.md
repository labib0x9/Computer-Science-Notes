## Overview

This program demonstrates how to stream the real-time output of a long-running background task to an HTTP response using `io.Pipe` and `http.Flusher`. It shows how asynchronous background worker goroutines can write logs that are immediately flushed over chunked HTTP transfer encoding to waiting clients.

## Concepts used

- Synchronous in-memory streaming with `io.Pipe`

- Chunked Transfer-Encoding in HTTP/1.1
- Coordinating reader/writer goroutines with channels

## How it works

When a request arrives at `/job`:
1. `io.Pipe()` creates an in-memory pipe with connected `logReader` and `logWriter`.
2. A background worker goroutine `longRunningProcess(logWriter)` simulates a 5-step process. Every second, it formats a JSON progress line and writes it to `logWriter`. Upon finishing, it closes `logWriter`.
3. In `processStreamer(logReader, w, done)`:
   - It asserts that `w` implements `http.Flusher`.
   - It continuously reads chunks from `logReader` and writes them to `w`.
   - After each write, it calls `flusher.Flush()`, pushing buffered bytes to the client socket immediately.
   - When `logReader` reaches EOF, it signals completion on the `done` channel.
4. The handler waits on `<-done` before returning.

## Key excerpt

```go
func processStreamer(logReader *io.PipeReader, w http.ResponseWriter, done chan struct{}) {
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Streaming unsupported!", http.StatusInternalServerError)
		return
	}

	buf := make([]byte, 1024)
	for {
		n, err := logReader.Read(buf)
		if n > 0 {
			w.Write(buf[:n])
			flusher.Flush()
		}
		if err != nil {
			break
		}
	}
	close(done)
}
```

## Things to watch

- **Pipe blocking**: Writes to an `io.PipeWriter` block until a matching `Read` from the `io.PipeReader` consumes the bytes. The writer and reader must run in separate goroutines.
- **Client disconnects**: If the client aborts the request midway, writing to `w` eventually fails, but the background goroutine might continue running unless wired to `r.Context()`.

## Terms

- **io.Pipe**: Creates a synchronous in-memory pipe that connects an `io.Reader` and an `io.Writer`.
- **http.Flusher**: An optional interface implemented by `ResponseWriter` allowing an HTTP handler to flush buffered data to the client.
