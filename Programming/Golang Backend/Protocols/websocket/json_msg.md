## Overview

This program demonstrates how to establish bidirectional, full-duplex communication over WebSockets using the `github.com/gorilla/websocket` package. It handles JSON serialization and deserialization across WebSocket frames and demonstrates request deadlines and graceful server shutdown.

## Concepts used

- WebSocket handshake upgrading with `websocket.Upgrader`
- Structured JSON reading and writing with `conn.ReadJSON` and `conn.WriteJSON`
- Connection read deadlines via `conn.SetReadDeadline`
- HTTP server graceful shutdown using `server.Shutdown`

## How it works

The program configures a `websocket.Upgrader` with `CheckOrigin` returning `true` to accept cross-origin WebSocket connections.

When a client hits `GET /echo`:
1. `upgrader.Upgrade(w, r, http.Header{})` performs the HTTP-to-WebSocket protocol upgrade.
2. It derives a 40-second timeout context from `r.Context()` and sets a read deadline on the socket with `conn.SetReadDeadline(deadline)`.
3. In a loop:
   - `conn.ReadJSON(&ID)` parses incoming JSON into struct `A` (which contains `Id int`).
   - `ID.Increment()` increments the integer.
   - `conn.WriteJSON(&ID)` serializes the struct back to the client over the socket.
   - If an error or socket disconnection occurs, the loop breaks and the socket is closed via `defer conn.Close()`.

In `main`, the handler is mounted on `/echo` on port `:8080`.

## Key excerpt

```go
type A struct {
	Id int `json:"req_id"`
}

func (a *A) Increment() {
	a.Id++
}

func handleConn(w http.ResponseWriter, r *http.Request) {
	conn, err := upgrader.Upgrade(w, r, http.Header{})
	if err != nil {
		http.Error(w, "internal server error", http.StatusInternalServerError)
		return
	}
	defer conn.Close()

	ctx, cancel := context.WithTimeout(r.Context(), 40*time.Second)
	defer cancel()

	if deadline, ok := ctx.Deadline(); ok {
		_ = conn.SetReadDeadline(deadline)
	}

	for {
		var ID A
		if err := conn.ReadJSON(&ID); err != nil {
			break
		}
		ID.Increment()
		if err := conn.WriteJSON(&ID); err != nil {
			break
		}
	}
}
```

## Things to watch

- **Sequential synchronous execution in main**: In `main()`, `server.ListenAndServe()` blocks until the server stops; code following it (calling `server.Shutdown`) will only execute after `ListenAndServe` returns an error, meaning `server.Shutdown` won't trigger while the server is running.
- **Deadline renewal**: `SetReadDeadline` sets a single absolute timestamp. For long-lived idle connections with heartbeats, the deadline must be refreshed upon each successful read or ping.
