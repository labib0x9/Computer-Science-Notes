## Overview

This program demonstrates handling raw WebSocket frames using `github.com/gorilla/websocket`. It inspects the WebSocket opcode (`TextMessage` vs `BinaryMessage`) and conditionally replies with modified text or binary data.

[text_binary_frame.go](https://github.com/labib0x9/Programming-Notes/blob/main/Programming/Golang%20Backend/Protocols/websocket/text_binary_frame.go)

## Concepts used

- WebSocket frame types and opcodes (`TextMessage = 1`, `BinaryMessage = 2`)
- Low-level frame reading using `conn.ReadMessage()`
- Low-level frame writing using `conn.WriteMessage()`
- Client connection tracking and logging

## How it works

The program initializes a `websocket.Upgrader` accepting all origins.

In `handleConn`:
1. `upgrader.Upgrade` upgrades the HTTP GET request to a WebSocket connection.
2. A 40-second timeout context sets a read deadline on the underlying connection.
3. In a loop, `conn.ReadMessage()` blocks until a full message frame arrives, returning `msgType`, raw byte slice `msg`, and any `err`.
4. It logs the client remote address, message type integer, and message text to stdout.
5. It inspects `msgType`:
   - Case `1` (Text Frame): Replies using `conn.WriteMessage` with `msgType = 1` and content `<msg> -> server`.
   - Case `2` (Binary Frame): Replies with `msgType = 2` and byte content `server is working broo`.
6. When client closes connection or encounters error, the loop exits and the socket closes.

## Key excerpt

```go
	for {
		msgType, msg, err := conn.ReadMessage()
		if err != nil {
			// what to do?
			break
		}

		fmt.Println("Client:", r.RemoteAddr, "MSG TYPE:", msgType, ", MSG:", string(msg))

		switch msgType {
		case 1:
			_ = conn.WriteMessage(msgType, []byte(string(msg)+" -> server"))
		case 2:
			_ = conn.WriteMessage(msgType, []byte("server is working broo"))
		}
	}
```

## Things to watch

- **Magic numbers for frame types**: The code uses literal constants `case 1:` and `case 2:`. Idiomatic Gorilla WebSocket code uses package constants `websocket.TextMessage` (1) and `websocket.BinaryMessage` (2).
- **Graceful shutdown order**: As in `json_msg.go`, `server.ListenAndServe()` blocks synchronously before `server.Shutdown(ctx)` in `main`.

## Terms

- **Opcode**: A 4-bit field in a WebSocket frame header that defines the frame type (continuation, text, binary, close, ping, pong).
- **Text Frame (1)**: A frame containing UTF-8 encoded string data.
- **Binary Frame (2)**: A frame containing arbitrary binary byte data.
