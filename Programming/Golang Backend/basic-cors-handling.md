## Overview

This program demonstrates manual handling of Cross-Origin Resource Sharing (CORS) headers within standard Go HTTP handlers using `net/http`. It serves static topic metadata encoded in JSON while allowing cross-origin requests from any client domain.

## Concepts used

- HTTP request handling via `net/http.ServeMux` and `http.HandlerFunc`
- Response header manipulation with `http.ResponseWriter.Header().Set`
- Cross-Origin Resource Sharing headers (`Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`)
- JSON payload encoding using `json.NewEncoder`
- Package initialization via `init`

## How it works

The program defines a `Topic` struct to represent learning tracks. In the `init` function, two initial topics (`linux` and `ccode`) are created and appended to the global slice `AllTopics`.

When an incoming request reaches `getAllTopics`:
1. It injects CORS headers onto the `http.ResponseWriter`: setting `Access-Control-Allow-Origin` to `*` and `Access-Control-Allow-Methods` to `OPTION, GET`.
2. It evaluates the request method using a switch statement. If `r.Method` is `http.MethodGet`, it marks the `Content-Type` as `application/json` and serializes `AllTopics` to the response stream using `json.NewEncoder(w).Encode`.
3. If any other HTTP method is used, it returns an HTTP 400 Bad Request error via `http.Error`.

The `main` function mounts `getAllTopics` to `/getAllTopics` on a new `http.ServeMux` and starts listening on `:8080`.

## Key excerpt

```go
func getAllTopics(w http.ResponseWriter, r *http.Request) {

	// CORS - handling
	w.Header().Set("Access-Control-Allow-Origin", "*")
	// w.Header().Set("Access-Control-Allow-Origin", "http://url")

	w.Header().Set("Access-Control-Allow-Methods", "OPTION, GET")

	switch r.Method {
	case http.MethodGet:

		w.Header().Set("Content-Type", "application/json")

		encoder := json.NewEncoder(w)
		encoder.Encode(AllTopics)

	default:
		http.Error(w, "method not allowed", http.StatusBadRequest)
	}
}
```

## Expected behavior (from reading the code, not run)

- Sending a `GET` request to `http://localhost:8080/getAllTopics` returns HTTP status 200 with headers `Access-Control-Allow-Origin: *` and a JSON array containing two topic objects.
- Sending a `POST` or other non-GET request responds with HTTP status 400 and the message `method not allowed`.
- Preflight `OPTIONS` requests hit the default branch and return status 400 rather than standard 200 or 204 preflight responses.

## Things to watch

- **OPTIONS method handling**: The handler declares `OPTION, GET` in `Access-Control-Allow-Methods`, but preflight `OPTIONS` requests trigger the `default` switch branch, returning HTTP 400 instead of a successful preflight status (such as 200 OK or 204 No Content).
- **Wildcard CORS in production**: Allowing `*` allows any origin to read public data, which is fine for public APIs but unsafe if credentials or cookies are involved.
- **Typo in standard method**: The header string uses `OPTION` instead of standard `OPTIONS`.

## Terms

- **CORS**: Cross-Origin Resource Sharing, a browser mechanism controlling how resources on one origin are requested by another.
- **Preflight request**: An `OPTIONS` request sent by browsers before certain cross-origin requests to check permissions.
- **json.Encoder**: A streaming JSON serializer writing directly to an `io.Writer`.
