## Overview

This program demonstrates wrapping a standard Go `http.ServeMux` inside a global router handler. The wrapper intercepts all incoming traffic to provide unified CORS headers and preflight handling before delegating request dispatching to the underlying mux.

## Concepts used

- HTTP middleware chaining and global router wrapping

## How it works

The program populates a global slice `AllTopics` during `init`. It registers two endpoint handlers:
- `getAllTopics`: Encodes the entire `AllTopics` slice as JSON.
- `getTopics`: Encodes only the first element (`AllTopics[0]`) as JSON.

The core architectural pattern is the `GlobalRouter(mux *http.ServeMux) http.Handler` function:
1. It returns an `http.HandlerFunc` that wraps the provided `mux`.
2. For every incoming request, it sets `Access-Control-Allow-Origin: *` and `Access-Control-Allow-Methods: OPTION, GET`.
3. If the request method is `OPTIONS`, it short-circuits execution by setting HTTP status 204 (No Content) and returning immediately.
4. For all other methods, it delegates request execution to `mux.ServeHTTP(w, r)`.

In `main`, the handlers are mounted to `/getAllTopics` and `GET /get/topics`. The mux is passed to `GlobalRouter`, which is then served by `http.ListenAndServe(":8080", ...)`.

## Key excerpt

```go
func GlobalRouter(mux *http.ServeMux) http.Handler {
	handlerAllReq := func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Access-Control-Allow-Origin", "*")
		w.Header().Set("Access-Control-Allow-Methods", "OPTION, GET")
		if r.Method == "OPTIONS" {
			w.WriteHeader(http.StatusNoContent)
			return
		}

		mux.ServeHTTP(w, r)
	}

	return http.HandlerFunc(handlerAllReq)
}
```

## Expected behavior (from reading the code, not run)

- An `OPTIONS` request to any path returns HTTP 204 No Content with CORS headers.
- A `GET` request to `/getAllTopics` returns HTTP 200 with all topics in a JSON list.
- A `GET` request to `/get/topics` returns HTTP 200 with the single Linux topic object.
- Any request with unsupported methods or unmapped routes returns the standard mux 404 or 405 response while retaining CORS headers.

## Things to watch

- **Go 1.22+ routing syntax**: The route `GET /get/topics` uses Go 1.22's method-matching pattern in `ServeMux`. On Go versions prior to 1.22, this pattern is treated as a literal path including the method string.
- **Missing allowed headers**: For complex cross-origin requests, browsers may send `Access-Control-Request-Headers`, which requires setting `Access-Control-Allow-Headers`.

## Terms

- **ServeMux**: The standard Go HTTP request multiplexer that routes incoming URLs to registered handlers.
- **Preflight 204**: An HTTP status indicating the server successfully acknowledged options with no entity body.
