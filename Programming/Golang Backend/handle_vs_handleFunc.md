## Overview

This program demonstrates the difference between `ServeMux.HandleFunc` and `ServeMux.Handle` in Go's standard `net/http` package. It showcases how regular functions are registered directly or adapted into `http.Handler` instances via `http.HandlerFunc`.

## Concepts used

- The `http.Handler` interface (`ServeHTTP(ResponseWriter, *Request)`)
- The `http.HandlerFunc` adapter type

## How it works

The program defines two standard handler functions matching the signature `func(http.ResponseWriter, *http.Request)`:
- `getAllTopics`: Validates that the request method is `GET` and streams the JSON-encoded `AllTopics` slice.
- `getTopics`: Streams the first topic element as JSON.

In `main`:
1. An `http.NewServeMux()` router is created.
2. `mux.HandleFunc("/getAllTopics", getAllTopics)` registers `getAllTopics` directly because `HandleFunc` expects a function with the matching signature.
3. `mux.Handle("GET /get/topics", http.HandlerFunc(getTopics))` registers `getTopics` using `mux.Handle`. Because `Handle` requires an object implementing `http.Handler`, `http.HandlerFunc(getTopics)` converts the function into an adapter type implementing `ServeHTTP`.
4. The server starts listening on `:8080`.

## Key excerpt

```go
func main() {

	mux := http.NewServeMux()

	mux.HandleFunc("/getAllTopics", getAllTopics)
	mux.Handle("GET /get/topics", http.HandlerFunc(getTopics))

	slog.Info("Starting Server at http://127.0.0.1:8080/")
	log.Fatal(http.ListenAndServe(":8080", mux))
}
```

## Things to watch

- **Interface vs Function Adapter**: `HandleFunc(pattern, fn)` is simply syntactic sugar for `Handle(pattern, http.HandlerFunc(fn))`.
- **Go 1.22 Method Matching**: `GET /get/topics` specifies an HTTP method prefix supported natively in Go 1.22+.

## Terms

- **http.Handler**: The core Go HTTP interface requiring a `ServeHTTP(ResponseWriter, *Request)` method.
- **http.HandlerFunc**: An adapter type that allows the use of ordinary functions as HTTP handlers.
