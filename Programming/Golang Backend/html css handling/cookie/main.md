## Overview

This program demonstrates how to set and read cookies across cross-origin HTTP requests in Go. It shows how to satisfy browser security requirements for credentialed cross-origin requests by dynamically reflecting the request `Origin` header and configuring `SameSite=None` and `Secure=true`.

## How it works

The code implements a middleware wrapper `withCORS`:
1. When credentials (`Access-Control-Allow-Credentials: true`) are sent, browsers reject wildcard `*` origins. Thus, `withCORS` inspects `r.Header.Get("Origin")` and echoes that specific origin back in `Access-Control-Allow-Origin`.
2. It sets `Access-Control-Allow-Credentials: true` and approves `GET, OPTIONS` methods.
3. For preflight `OPTIONS` requests, it returns status 204 No Content immediately.

Two routes are registered:
- `/set-cookie`: Issues an HTTP cookie named `testcookie` with value `hello`, `Path: "/"`, `HttpOnly: false`, `Secure: true`, and `SameSite: http.SameSiteNoneMode`.
- `/check-cookie`: Reads `testcookie` using `r.Cookie("testcookie")`. If found, it prints the cookie name and value; otherwise, it returns HTTP 404.

In `main`, both routes are wrapped with `withCORS` and served on `:8080`.

## Key excerpt

```go
func setCookieHandler(w http.ResponseWriter, r *http.Request) {
	http.SetCookie(w, &http.Cookie{
		Name:     "testcookie",
		Value:    "hello",
		Path:     "/",
		HttpOnly: false, // false so the page can also show it via document.cookie
		Secure:   true,  // required when SameSite=None
		SameSite: http.SameSiteNoneMode,
	})
	fmt.Fprintln(w, "cookie set")
}
```

## Expected behavior (from reading the code, not run)

- A request to `/set-cookie` sets the `Set-Cookie` response header with `testcookie=hello; Path=/; Secure; SameSite=None`.
- Subsequent requests including the cookie to `/check-cookie` output `received cookie: testcookie=hello`.
- Calling `/check-cookie` without the cookie responds with HTTP 404 and `no cookie received: http: named cookie not present`.

## Things to watch

- **SameSite=None requires Secure**: Modern browsers reject any cookie configured with `SameSite=None` unless the `Secure` flag is also enabled (which requires HTTPS in production, though browsers permit it over `localhost`).
- **HttpOnly implications**: `HttpOnly: false` allows client-side JavaScript access via `document.cookie`, which makes cookies accessible to scripts but exposes them to Cross-Site Scripting (XSS) extraction.

## Terms

- **SameSite=None**: Allows cookies to be sent across cross-site requests (e.g. third-party API calls).
- **Access-Control-Allow-Credentials**: Header indicating whether the response to a cross-origin request can be exposed when credentials flag is true.
