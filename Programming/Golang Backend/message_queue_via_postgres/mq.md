## Overview

This program demonstrates how to build a transactional, relational message queue using PostgreSQL and Go with `github.com/jmoiron/sqlx` and `github.com/lib/pq`. It provisions isolated database schemas, custom enum types, message tables, and stored functions to enqueue and atomically dequeue messages.

## Concepts used

- Database schema and DDL automation via `sqlx.DB`
- Custom PostgreSQL ENUM types (`queue_state`)
- Stored PL/pgSQL functions for atomic enqueue and dequeue operations
- Row-level concurrency control using `SELECT ... FOR UPDATE SKIP LOCKED`
- JSON payload handling using PostgreSQL `jsonb`

## How it works

The implementation establishes a PostgreSQL connection to `localhost:5432` with user `postgres` and database `queue`:
1. `createSchema` and `listSchemaTables`: Sets up a dedicated schema named `user_event`.
2. `createEnum`: Defines a PostgreSQL type `queue_state` with values `enqueued`, `processing`, `completed`, and `failed`.
3. `createTable`: Creates table `events` with columns `id`, `payload` (JSONB), `retry_count`, `created_at`, `updated_at`, and `state`.
4. `createEnqueueFunction`: Provisions a stored procedure `enqueue` that inserts new rows into `events` with `enqueued` status and sends an asynchronous `pg_notify`.
5. `createDequeueFunction`: Provisions a stored procedure `dequeue` that queries rows in `enqueued` state using `FOR UPDATE SKIP LOCKED`, transitions them to `processing`, updates `updated_at`, and returns them.
6. `enqueue` and `dequeue`: High-level Go helpers that execute the stored procedures and deserialize returned payloads into `QueueRow` and `Payload` structs.

In `main`, these steps are run sequentially to configure the database schema, enqueue a sample message, and verify queue state.

## Key excerpt

```go
func createDequeueFunction(ctx context.Context, conn *sqlx.DB) {
	query := `
CREATE OR REPLACE FUNCTION dequeue(p_limit INT)
RETURNS SETOF events AS $$
BEGIN
    RETURN QUERY
    WITH selected_rows AS (
        SELECT id
        FROM events
        WHERE state = 'enqueued'
        ORDER BY created_at ASC
        LIMIT p_limit
        FOR UPDATE SKIP LOCKED
    )
    UPDATE events e
    SET state = 'processing',
        updated_at = NOW()
    FROM selected_rows sr
    WHERE e.id = sr.id
    RETURNING e.*;
END;
$$ LANGUAGE plpgsql;
	`
	_, err := conn.ExecContext(ctx, query)
	if err != nil {
		panic(err)
	}
}
```

## Things to watch

- **Database credentials**: Connection string `postgres://postgres:postgres@localhost:5432/queue?sslmode=disable` is hardcoded; in production, use environment variables.
- **FOR UPDATE SKIP LOCKED**: This Postgres feature allows multiple concurrent worker goroutines or processes to dequeue distinct batches of tasks without blocking each other.

## Terms

- **SKIP LOCKED**: A SQL concurrency clause that skips rows currently locked by other concurrent transactions rather than waiting.
- **JSONB**: PostgreSQL binary representation of JSON providing efficient indexing and parsing.
