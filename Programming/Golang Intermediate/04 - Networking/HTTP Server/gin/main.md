## Overview

This program demonstrates how to build high-performance web applications using the Gin web framework (`github.com/gin-gonic/gin`) in Go. It illustrates router setup, mounting custom timing middleware with `ctx.Next()`, and serving JSON responses.

## Concepts used

- The Gin engine (`gin.Default()`, `gin.New()`)
- Custom middleware returning `gin.HandlerFunc`
- Controlling middleware flow with `ctx.Next()`
- Serializing JSON responses with `ctx.JSON()`

## How it works

1. `Logger() gin.HandlerFunc`:
   - Intercepts requests, calls `ctx.Next()` to yield execution to downstream handlers, and calculates execution latency afterwards.
   - Logs request metadata and duration via `slog.Info`.
2. In `main()`:
   - Initializes a new Gin router: `r := gin.New()`.
   - Attaches `Logger()` via `r.Use(Logger())`.
   - Defines endpoint `GET /ping`:
     ```go
     r.GET("/ping", func(c *gin.Context) {
         c.JSON(http.StatusOK, gin.H{"message": "pong"})
     })
     ```
   - Starts the server on `:8080` with `r.Run(":8080")`.

## Key excerpt

```go
func Logger() gin.HandlerFunc {
	return func(ctx *gin.Context) {
		start := time.Now()
		ctx.Next()
		latency := time.Since(start)
		slog.Info("Request",
			"status", ctx.Writer.Status(),
			"method", ctx.Request.Method,
			"path", ctx.Request.URL.Path,
			"latency", latency,
		)
	}
}
```

## Things to watch

- **ctx.Next vs Return**: Code preceding `ctx.Next()` runs before the route handler; code following `ctx.Next()` runs after the route handler completes.
- **gin.H**: An alias for `map[string]any` provided by Gin for constructing JSON objects.

## Terms

- **Gin**: A high-performance HTTP web framework for Go featuring a martini-like API with custom Radix tree routing.
- **gin.Context**: The core context object in Gin containing request metadata, response writers, and parameter extractors.
