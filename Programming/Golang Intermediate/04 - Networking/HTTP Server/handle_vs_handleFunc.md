## Overview

This program demonstrates the difference between `http.HandleFunc` and `http.Handle` in Go's standard `net/http` package. It shows that both methods register routes on a `ServeMux`, with `HandleFunc` accepting a function signature directly and `Handle` accepting an object satisfying the `http.Handler` interface.

## Concepts used

- The `http.Handler` interface (`ServeHTTP(ResponseWriter, *Request)`)
- The `http.HandlerFunc` adapter type
- Registering routes with `http.HandleFunc` vs `http.Handle`
- Writing response byte streams with `w.Write`

## How it works

1. It defines `apiHandler(w http.ResponseWriter, r *http.Request)`:
   - Writes `"Hello World\r\n"` to the HTTP response stream.
2. In `main()`:
   - Option 1: `http.HandleFunc("/api", apiHandler)` registers the function directly.
   - Option 2: `http.Handle("/api", http.HandlerFunc(apiHandler))` wraps the function using the `http.HandlerFunc` adapter to satisfy `http.Handler` before registering.
3. The server begins listening on port 8080.

func main() {
	// Both does the same purpose

- Starts an HTTP server on `:8080`.

## Things to watch

- **Under the hood**: `http.HandleFunc` simply calls `DefaultServeMux.Handle(pattern, HandlerFunc(handler))` internally; the two methods are functionally identical.

## Terms

- **ServeMux**: The standard HTTP request multiplexer that matches URL paths to handlers.
- **HandlerFunc**: A function type adapter that implements `ServeHTTP` by calling itself.
