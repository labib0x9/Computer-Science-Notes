## Overview

This program demonstrates how to check for specific sentinel error values within wrapped error chains in Go using `errors.Is`. It illustrates why `errors.Is` must be used instead of the direct equality operator `==` when errors are wrapped with `%w`.

## Concepts used

- Package-level sentinel errors (`var Err = errors.New(...)`)
- Error wrapping with `fmt.Errorf("%w", Err)`
- Recursive error tree inspection with `errors.Is`
- Failure of direct `==` comparisons on wrapped errors

## How it works

1. It defines package sentinel `var Err = errors.New("error")`.
2. It wraps `Err` with additional context: `e := fmt.Errorf("Error Cause: %w", Err)`.
3. In `main()`:
   - Calling `errors.Is(e, Err)` returns `true` because `errors.Is` unwraps the error chain.
   - In contrast, direct comparison `e == Err` would evaluate to `false` because `e` is a new wrapper error struct.

## Key excerpt

```go
var Err = errors.New("error")

func main() {
	e := fmt.Errorf("Error Cause: %w", Err)

	if errors.Is(e, Err) {
		fmt.Println("Found the sentinel error!")
	}
}
```
