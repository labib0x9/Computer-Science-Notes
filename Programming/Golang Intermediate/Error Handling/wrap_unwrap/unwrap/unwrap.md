## Overview

This program demonstrates how to unpack nested error hierarchies in Go. It shows how `errors.Unwrap` strips outer error layers one by one and how `errors.As` finds and extracts specific error types from anywhere in the error chain.

## Concepts used

- Single-step unwrapping with `errors.Unwrap`
- Target type searching with `errors.As`
- Contextual error wrapping with `fmt.Errorf("%w")`
- Handling filesystem errors (`os.PathError`)

## How it works

1. `OpenFile(path)` attempts `os.Open(path)` and wraps any failure with timestamp context: `fmt.Errorf("access failed at %v: %w", time.Now(), err)`.
2. In `main`:
   - It captures the error.
   - It calls `errors.Unwrap(err)` to peel off the outer timestamp string, revealing the underlying `os.PathError`.
   - It calls `var pathErr *os.PathError; if errors.As(err, &pathErr) { ... }` to automatically extract the path error struct without manual unwrapping loops.

## Key excerpt

```go
func OpenFile(path string) error {
	file, err := os.Open(path)
	if err != nil {
		return fmt.Errorf("failed to open file at %v: %w", time.Now(), err)
	}
	defer file.Close()
	return nil
}

func main() {
	err := OpenFile("non_existent_file.txt")
	var pathErr *os.PathError
	if errors.As(err, &pathErr) {
		fmt.Println("Path error detected on:", pathErr.Path)
	}
}
```

## Things to watch

- **errors.As destination requirement**: The second parameter of `errors.As` must be a pointer to an interface or a pointer to a type implementing `error`; passing a non-pointer panics at runtime.

## Terms

- **errors.Unwrap**: Returns the result of calling the `Unwrap` method on an error, or `nil` if the error has no `Unwrap` method.
