## Overview

This program demonstrates a concurrency livelock in Go, modeling two polite pedestrians trying to pass each other in a narrow hallway who repeatedly change directions in sync without moving forward.

## Concepts used

- Livelock vs Deadlock characteristics

- Active looping without useful state progression

## How it works

1. Two people approach each other.
2. When person A notices person B in front, A steps aside to the right.
3. Simultaneously, person B notices person A and also steps to their right.
4. Both detect they are still blocked, step left simultaneously, and repeat indefinitely.
5. CPU usage remains high while zero forward progress is achieved.

## Key excerpt

```go
// Pedestrians constantly step aside for one another
// Active state changes continue, but zero forward progress is made:
for {
	if blocked() {
		stepAside()
		continue
	}
	moveForward()
	break
}
```

## Expected behavior (from reading the code, not run)

- Logs continuous oscillation between states while neither goroutine ever reaches its destination.

## Things to watch

- Unlike deadlock where goroutines sleep with zero CPU usage, livelock consumes active CPU cycles while remaining functionally stuck. Adding randomized backoff delays breaks livelocks.

## Terms

- **Livelock**: A concurrency anomaly where two or more processes continuously change their state in response to each other without making any practical progress.
