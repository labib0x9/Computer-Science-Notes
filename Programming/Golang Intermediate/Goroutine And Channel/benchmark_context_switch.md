## Overview

This program defines a benchmark measuring the context-switching latency between two goroutines communicating across unbuffered channels, contrasting lightweight user-space goroutine switches with OS thread switches.

## How it works

1. Allocates two unbuffered channels: `begin := make(chan struct{})` and `c := make(chan struct{})`.
2. Spawns two goroutines that alternate sending and receiving tokens across the channels.
3. Uses `b.ResetTimer()` to isolate the switching loop from test setup.
4. Each iteration executes two channel operations, forcing the Go runtime scheduler to switch between goroutines.

## Key excerpt

```go
func BenchmarkContextSwitch(b *testing.B) {
	var wg sync.WaitGroup
	begin := make(chan struct{})
	c := make(chan struct{})

	var token struct{}
	sender := func() {
		defer wg.Done()
		<-begin
		for i := 0; i < b.N; i++ {
			c <- token
		}
	}
	receiver := func() {
		defer wg.Done()
		<-begin
		for i := 0; i < b.N; i++ {
			<-c
		}
	}
```

## Expected behavior (from reading the code, not run)

- Running `go test -bench=BenchmarkContextSwitch` reveals switching overhead on modern CPUs (typically ~100-250 nanoseconds per context switch).

## Things to watch

- Benchmarks must be invoked using `go test -bench=.`; running via `go run` does nothing because `main()` is not invoked by the testing harness.

## Terms

- **Context switch**: The process of saving and restoring the execution state of a thread or goroutine so that execution can be resumed later.
- **M:N Scheduler**: The Go runtime multiplexer mapping $M$ goroutines onto $N$ OS threads.
