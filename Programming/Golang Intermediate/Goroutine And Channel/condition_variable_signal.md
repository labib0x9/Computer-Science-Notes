## Concepts used

- Condition variables via `sync.NewCond(&sync.Mutex{})`
- Suspended waiting with `c.Wait()` inside a predicate loop
- Resumption signaling with `c.Signal()`

## How it works

1. Initializes `c := sync.NewCond(&sync.Mutex{})` and an empty slice `queue`.
2. Consumer locks mutex: `c.L.Lock()`.
3. Checks predicate in a loop: `for len(queue) == 0 { c.Wait() }`. `Wait()` releases the lock and blocks until signaled.
4. Producer locks mutex, enqueues item, calls `c.Signal()`, and unlocks.
5. Consumer wakes up, reacquires lock, and dequeues the item safely.

## Key excerpt

```go
c := sync.NewCond(&sync.Mutex{})
queue := make([]interface{}, 0, 10)

removeFromQueue := func(delay time.Duration) {
	time.Sleep(delay)
	c.L.Lock()
	queue = queue[1:]
	fmt.Println("Removed from queue")
	c.L.Unlock()
	c.Signal()
}
```

## Things to watch

- Always call `c.Wait()` inside a `for` loop, never an `if` statement, to guard against spurious wakeups and race conditions before lock reacquisition.

## Terms

- **sync.Cond**: A synchronization primitive that coordinates goroutines waiting for or announcing arbitrary conditions.
- **Spurious wakeup**: A condition where a waiting thread awakens without an explicit signal having been sent.
