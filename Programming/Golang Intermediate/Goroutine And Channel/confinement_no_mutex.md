## Overview

This program illustrates lexical data confinement in Go, demonstrating how ownership of mutable state can be confined to a single goroutine or sequenced through channels to avoid data races without mutexes.

## Concepts used

## How it works

1. Demonstrates an increment counter pattern.
2. Rather than wrapping mutations with `sync.Mutex`, operations are piped through communication channels where a designated worker holds sole ownership of the variable.
3. Coordinates completion with `sync.WaitGroup`.

## Key excerpt

```go
number := 0
var wg sync.WaitGroup

// Confines mutable state to sequential channel communications:
ch := make(chan int)
go func() {
	for val := range ch {
		number += val
	}
}()
```

## Things to watch

- Go motto: "Do not communicate by sharing memory; instead, share memory by communicating." Confinement makes data races structurally impossible.

## Terms

- **Data confinement**: Ensuring that access to mutable state is restricted to a single concurrent entity at any given time.
- **Shared memory**: Memory locations accessible simultaneously by multiple threads of execution.
