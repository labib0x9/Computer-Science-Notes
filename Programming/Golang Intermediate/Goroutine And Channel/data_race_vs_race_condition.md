## How it works

1. Sets up unsynchronized map reads and writes in multiple goroutines to trigger a classic data race.
2. Contrasts with properly locked operations that still produce incorrect output due to non-deterministic execution ordering (a pure logical race condition).

## Key excerpt

```go
// Data race: concurrent unsynchronized reads/writes to shared state
go func() {
	m["foo"] = 1
}()
go func() {
	m["bar"] = 2
}()
```

## Expected behavior (from reading the code, not run)

- Running with `go run -race` flags concurrent map read/write access and aborts execution with a fatal runtime crash.

## Things to watch

- A program can be completely free of data races (using locks everywhere) but still have severe race conditions if business transaction order is non-deterministic.

## Terms

- **Data race**: Concurrent access to the same memory location where at least one access is a write and there is no synchronization.
- **Race condition**: A defect where the program outcome depends on the uncontrollable timing or interleaving of concurrent operations.
