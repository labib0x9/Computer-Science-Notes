## Overview

This program demonstrates a classic circular wait deadlock in Go, where two concurrent routines attempt to acquire two distinct `sync.Mutex` locks in opposite orders.

## Concepts used

- Coffman circular wait condition
- Lock acquisition order inversion
- Fatal runtime deadlock detection

## How it works

1. Defines two mutexes: `mu1` and `mu2`.
2. Goroutine A locks `mu1`, sleeps briefly, and tries to acquire `mu2`.
3. Goroutine B locks `mu2`, sleeps briefly, and tries to acquire `mu1`.
4. Both goroutines block indefinitely waiting for the other to release the needed lock.

## Key excerpt

```go
// Goroutine 1 acquires mu1 then mu2:
go func() {
	mu1.Lock()
	time.Sleep(100 * time.Millisecond)
	mu2.Lock()
	// ...
}()

// Goroutine 2 acquires mu2 then mu1 (inverted order):
go func() {
	mu2.Lock()
	time.Sleep(100 * time.Millisecond)
	mu1.Lock()
	// ...
}()
```

## Expected behavior (from reading the code, not run)

- Crashes with: `fatal error: all goroutines are asleep - deadlock!`.

## Things to watch

- Deadlock prevention rule: always establish and adhere to a strict global hierarchy for lock acquisition ordering across all goroutines.

## Terms

- **Circular wait**: A condition where process A waits for a resource held by B, and B waits for a resource held by A.
