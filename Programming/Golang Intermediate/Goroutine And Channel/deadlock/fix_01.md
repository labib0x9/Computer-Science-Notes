## Overview

This program demonstrates the resolution of the circular wait deadlock in `example_01.go` by enforcing a uniform lock acquisition ordering (`mu1` then `mu2`) across all goroutines.

## How it works

1. Both goroutines are restructured to acquire `mu1.Lock()` first, followed by `mu2.Lock()`.
2. The second goroutine is prevented from acquiring `mu2` until the first goroutine releases `mu1` and completes its critical section.
3. Eliminates circular dependencies completely.

## Key excerpt

```go
// Both goroutines acquire locks in the identical order:
go func() {
	mu1.Lock()
	mu2.Lock()
	// critical section
	mu2.Unlock()
	mu1.Unlock()
}()

go func() {
	mu1.Lock()
	mu2.Lock()
	// critical section
	mu2.Unlock()
	mu1.Unlock()
}()
```

- Both goroutines execute sequentially without deadlocking and terminate cleanly.

## Things to watch

- Always unlock in reverse order of acquisition (`mu2.Unlock()` then `mu1.Unlock()`) or use `defer`.

## Terms

- **Lock hierarchy**: A design discipline that assigns a global order to locks to guarantee deadlock-free acquisition.
