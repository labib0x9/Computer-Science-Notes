## Overview

This program demonstrates what occurs when a struct containing a `sync.Mutex` is passed by value: copying the struct duplicates the mutex state, creating two completely independent locks that fail to synchronize access.

## Concepts used

- Pass-by-value struct semantics

## How it works

1. `type value struct { mu sync.Mutex; val int }`.
2. Passes `value` by value to a function or copies it.
3. The copied instance gets its own separate mutex.
4. Locking one copy has zero effect on the other copy, breaking mutual exclusion without deadlocking.

## Key excerpt

```go
type value struct {
	mu  sync.Mutex
	val int
}

func inspect(v value) {
	v.mu.Lock()
	defer v.mu.Unlock()
	// Operates on a copy of the mutex!
}
```

## Expected behavior (from reading the code, not run)

- Does not deadlock, but fails to provide concurrency protection across goroutines.
- Running `go vet` warns: `passes lock by value: main.value contains sync.Mutex`.

## Things to watch

- Never copy values of type `sync.Mutex`. Always pass structs containing mutexes as pointers (`*value`).

## Terms

- **copylocks**: A Go vet check that flags any function that passes or returns values containing locks by value.
