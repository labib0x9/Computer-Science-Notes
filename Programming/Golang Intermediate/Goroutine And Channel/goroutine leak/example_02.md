## Overview

This program demonstrates a classic goroutine leak in Go: launching a goroutine that performs a send on an unbuffered channel when the parent caller has stopped reading from it.

## Concepts used

- Goroutine leak identification
- Permanent blocking on unbuffered channel sends
- Garbage collector limitations on blocked goroutines

## How it works

1. `main` spawns a background worker that does computational work and sends the result to an unbuffered channel `ch <- result`.
2. If `main` returns or stops reading from `ch` early (e.g. on error or timeout), the worker blocks indefinitely.
3. The blocked goroutine is retained in memory forever and cannot be garbage collected.

## Key excerpt

```go
func main() {
	ch := make(chan int)
	go func() {
		val := 42
		ch <- val // blocks indefinitely if main abandons ch!
	}()
	// main exits without reading, or abandons channel
}
```

## Expected behavior (from reading the code, not run)

- The background goroutine remains permanently alive in runtime memory until the process terminates.

## Things to watch

- To prevent leaks: use a buffered channel of capacity 1 (`make(chan int, 1)`) so the sender can exit, or pass a `context.Context` to signal cancellation.

## Terms

- **Goroutine leak**: A bug where a goroutine is started but never finishes, consuming memory and system resources indefinitely.
