## Overview

This program illustrates goroutine lifecycle mechanics in Go, showing that when the `main` goroutine completes its execution, all child background goroutines are instantly aborted without waiting.

## Concepts used

- Main goroutine lifecycle
- Immediate process exit on main termination
- Premature termination of unsynchronized child routines

## How it works

1. `main()` spawns `go test()` which attempts to loop and sleep.
2. `main()` does not synchronize or wait using channels or `sync.WaitGroup`.
3. `main()` returns immediately, causing the entire OS process to exit and abruptly killing the child goroutine mid-execution.

## Key excerpt

```go
// main goroutine = parent
// test() creates a goroutine from main goroutine
// parent dies -> spawned child goroutine dies
func main() {
	go test()
	// Exits immediately without waiting
}
```

- The program exits instantly, producing little to no console output from `test()`.

## Things to watch

- Never rely on `time.Sleep` in `main()` to keep child goroutines alive. Always use proper synchronization primitives (`sync.WaitGroup` or channels).

## Terms

- **Main goroutine**: The initial goroutine launched by the Go runtime to execute `main.main`.
- **Process exit**: System termination where all memory and background threads are reclaimed by the operating system.
