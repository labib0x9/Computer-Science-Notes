## Overview

This program empirically measures the memory footprint of a single goroutine in Go by sampling heap metrics via `runtime.ReadMemStats` before and after spawning 10,000 idle goroutines.

## Concepts used

- Runtime memory profiling via `runtime.ReadMemStats`
- Forcing garbage collection with `runtime.GC()`
- Goroutine initial stack sizing (~2KB per goroutine)

## How it works

1. `memConsumed()` forces GC and records `m.Alloc` memory usage.
2. Spawns 10,000 goroutines that block on a shared `noop` channel.
3. Computes the difference in consumed memory divided by 10,000.
4. Outputs the average memory consumed per goroutine in kilobytes.

## Key excerpt

```go
func memConsumed() uint64 {
	runtime.GC()
	var s runtime.MemStats
	runtime.ReadMemStats(&s)
	return s.Sys
}

var c <-chan interface{}
var wg sync.WaitGroup
noop := func() {
	wg.Done()
	<-c
}
```

## Expected behavior (from reading the code, not run)

- Calculates and prints an average memory footprint of approximately 2KB to 2.5KB per goroutine, dramatically smaller than typical OS thread stacks (1MB to 8MB).

## Things to watch

- Goroutine stacks grow and shrink dynamically as needed; they start small (2KB) and expand in segments up to 1GB on 64-bit systems.

## Terms

- **Goroutine stack**: Dynamically sized contiguous execution stack managed entirely in user space by the Go runtime.
- **runtime.MemStats**: Standard library struct detailing memory allocator and garbage collector statistics.
