## Overview

This program demonstrates a complete multi-user TCP chat room in Go, using a central broadcaster goroutine to multiplex incoming client messages to all active connected chat clients.

## How it works

1. Binds TCP listener on port 8080.
2. Central `broadcaster` goroutine owns the map of connected clients (`map[client]bool`) and listens on `entering`, `leaving`, and `messages` channels.
3. When a client connects, a dedicated outgoing channel is registered with the broadcaster.
4. When any client sends text, the broadcaster relays the message to every registered client's channel.
5. Handles client disconnection by unregistering channels cleanly.

## Key excerpt

```go
type client chan<- string

var (
	entering = make(chan client)
	leaving  = make(chan client)
	messages = make(chan string) // all incoming client messages
)

func broadcaster() {
	clients := make(map[client]bool) // all connected clients
	for {
		select {
		case msg := <-messages:
			for cli := range clients {
				cli <- msg
			}
		case cli := <-entering:
			clients[cli] = true
		case cli := <-leaving:
			delete(clients, cli)
			close(cli)
		}
	}
}
```

## Things to watch

- Single-threaded broadcaster ownership avoids mutex locks for client management.
- If a client's write buffer fills up, it can block the broadcaster unless per-client channels are buffered or slow clients are dropped.

## Terms

- **Broadcaster pattern**: A centralized event distribution pattern where incoming events are fanned out to all active subscribers.
