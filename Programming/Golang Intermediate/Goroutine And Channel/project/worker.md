## Overview

This program demonstrates bounded work queue design in Go, defining capacity constants (`MAX_QUEUE_ITEM`, `MAX_WORKER_COUNT`) and dispatching jobs to a bounded pool of workers.

[worker.go](https://github.com/labib0x9/Programming-Notes/blob/main/Programming/Golang%20Intermediate/Goroutine%20And%20Channel/project/worker.go)

## Concepts used

- Bounded channel configuration constants
- Decoupling task submission from worker processing
- Synchronization via `sync.WaitGroup`

## How it works

1. Defines `const MAX_QUEUE_ITEM = 10` and `MAX_WORKER_COUNT = 4`.
2. Creates task channel buffered to `MAX_QUEUE_ITEM`.
3. Spawns 4 persistent worker goroutines.
4. Producer enqueues work items without blocking until queue capacity is reached.

## Key excerpt

```go
const (
	MAX_QUEUE_ITEM   = 10
	MAX_WORKER_COUNT = 4
)

// Workers consume from queue until channel closed
```

## Things to watch

- Bounded queues provide backpressure: if workers cannot keep pace with producers, producers block, preventing memory exhaustion.

## Terms

- **Backpressure**: Resistance or resistance mechanism that halts producers when downstream consumers are saturated.
