This program demonstrates channel multiplexing using Go's `select` statement, evaluating communication readiness across multiple channels and handling concurrent message arrival.

## Concepts used

- The `select` statement for channel multiplexing
- Pseudorandom case selection when multiple channels are ready

## How it works

1. Allocates `adminSender` and `userSender` channels.
2. Spawns sender goroutines publishing messages concurrently.
3. The `select` block evaluates readiness of both channels.
4. If both channels have data available, Go chooses between them via a uniform pseudo-random selection to ensure fairness.

## Key excerpt

```go
var adminSender, userSender chan string
var wg sync.WaitGroup

select {
case msg := <-adminSender:
	fmt.Println("Admin:", msg)
case msg := <-userSender:
	fmt.Println("User:", msg)
}
```

## Expected behavior (from reading the code, not run)

- Receives and handles messages from whichever channel becomes ready first.

## Things to watch

- Go's `select` does NOT evaluate cases top-to-bottom like a regular `switch`. When multiple cases are ready simultaneously, it picks one pseudo-randomly to avoid channel starvation.

## Terms

- **select**: A control flow statement in Go that waits on multiple channel communication operations.
- **Starvation avoidance**: Random case selection preventing higher-listed channels from monopolizing execution.
