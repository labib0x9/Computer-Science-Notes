## Overview

This program demonstrates how a worker function produces messages into a send-only channel (`chan<- string`) and closes the channel upon completion so the receiver knows when to terminate.

## Concepts used

- Send-only channel parameters (`chan<- string`)
- Iterating channel messages until closure (`for msg := range ch`)
- Closing channels from the sender side

## How it works

1. `SendMessage(ch chan<- string, n int)` loops 5 times, sending formatted messages.
2. Calls `close(ch)` to signal that no further messages will be transmitted.
3. The receiving loop in `main` reads all messages and exits gracefully once closed.

## Key excerpt

```go
// Only sender chan
func SendMessage(ch chan<- string, n int) {
	for i := 0; i < 5; i++ {
		ch <- fmt.Sprintf("Worker-%d : %d", n, i)
	}
	close(ch)
}
```

## Expected behavior (from reading the code, not run)

- Emits 5 formatted worker messages and terminates cleanly.

## Things to watch

- Rule of thumb: Only the sender should close a channel, never the receiver. Closing a channel from multiple senders or sending to a closed channel panics.

## Terms

- **Channel close**: A built-in action that marks a channel as unable to accept further values while allowing remaining buffered values to be drained.
