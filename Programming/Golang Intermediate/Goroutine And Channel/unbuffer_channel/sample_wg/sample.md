## Overview

This program demonstrates how to safely close a shared communication channel fed by multiple concurrent sender goroutines using `sync.WaitGroup`.

## Concepts used

- `sync.WaitGroup` (`Add`, `Done`, `Wait`)
- Multiple concurrent senders on a single channel
- Safe channel closure via dedicated coordination goroutine

## How it works

1. Spawns multiple `SendMessage` workers writing into a single unbuffered channel.
2. Each worker calls `defer wg.Done()`.
3. A separate closer goroutine waits with `wg.Wait()` and invokes `close(ch)`.
4. Main goroutine drains the channel with `for msg := range ch`.

## Key excerpt

```go
func SendMessage(ch chan<- string, n int, wg *sync.WaitGroup) {
	defer wg.Done()
	for i := 0; i < 3; i++ {
		ch <- fmt.Sprintf("Worker-%d : %d", n, i)
	}
}

// In main:
go func() {
	wg.Wait()
	close(ch)
}()
```

## Expected behavior (from reading the code, not run)

- Prints messages from all workers and terminates cleanly without deadlocks or panics.

## Things to watch

- Always pass `*sync.WaitGroup` as a pointer. Passing `sync.WaitGroup` by value copies the struct, causing the wait condition to deadlock.

## Terms

- **sync.WaitGroup**: A synchronization primitive that blocks until a collection of goroutines have finished executing.
