## Overview

This program demonstrates a classic concurrency deadlock bug in Go: attempting to send into an unbuffered channel from the main goroutine before any background goroutine is listening.

## Concepts used

- Unbuffered channel blocking behavior
- Fatal runtime deadlock detection (`fatal error: all goroutines are asleep - deadlock!`)
- Proper sender and receiver ordering

## How it works

1. Analyzes code that attempts `ch <- value` on an unbuffered channel without an active receiver.
2. Because unbuffered channel sends block until a receiver is ready, the main thread halts.
3. The Go runtime detects that no other goroutines are runnable and triggers a fatal panic.

## Terms

- **Deadlock**: A state in which each member of a group is waiting for another member to take action, causing all progress to halt.
