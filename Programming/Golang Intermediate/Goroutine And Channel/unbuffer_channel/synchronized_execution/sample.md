## Overview

This program demonstrates unbuffered channel synchronization across 5 worker goroutines, using a blocking channel receive to sequence worker progress.

## Concepts used

- Unbuffered channel rendezvous semantics

- Sequential lock-step synchronization

## How it works

1. Creates `done := make(chan bool)`.
2. Loops 5 times, spawning a goroutine for each worker.
3. Worker prints its ID and sends `done <- true`.
4. Main loop blocks on `<-done`, forcing lock-step execution before spawning the next worker.

## Key excerpt

```go
done := make(chan bool)

for i := 0; i < 5; i++ {
	go func(n int) {
		fmt.Println("Worker: ", i)
		done <- true
	}(i)

	<-done // blocks until worker sends
}
```

## Expected behavior (from reading the code, not run)

- Workers execute in lock-step sequence, one by one.

## Things to watch

- Bug note: The closure declares parameter `n int` but prints loop variable `i` directly instead of parameter `n`. Prior to Go 1.22, loop variable capture could cause unexpected index printing.

## Terms

- **Rendezvous**: A synchronization model where sender and receiver must meet at the same point in time to transfer data across an unbuffered channel.
