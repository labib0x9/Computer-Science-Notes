## Overview

This program demonstrates foundational concurrency synchronization in Go using `sync.WaitGroup` to wait for a set of concurrent worker functions to finish printing squares before main exits.

## Concepts used

- `sync.WaitGroup` counter lifecycle
- Passing `*sync.WaitGroup` by pointer
- `defer wg.Done()` pattern

## How it works

1. `Print(i int, wg *sync.WaitGroup)` marks completion with `defer wg.Done()` and prints `i` and `i*i`.
2. In `main`, loops from 0 to $N-1$, calling `wg.Add(1)` before launching `go Print(i, &wg)`.
3. `wg.Wait()` blocks `main` until all worker goroutines invoke `Done()`.

## Key excerpt

```go
func Print(i int, wg *sync.WaitGroup) {
	defer wg.Done() // mark goroutine as done
	fmt.Println(i, i*i)
}

func main() {
	var wg sync.WaitGroup
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go Print(i, &wg)
	}
	wg.Wait()
}
```

## Expected behavior (from reading the code, not run)

- Prints numbers and their squares from 0 to 9 in non-deterministic order, waiting for all 10 before exiting.

## Things to watch

- Always call `wg.Add(1)` BEFORE spawning the goroutine. Calling `wg.Add` inside the goroutine creates a race condition where `Wait()` may return before the goroutine starts.

## Terms

- **sync.WaitGroup**: A counter-based synchronization primitive that blocks until its internal counter decrements to zero.
