## Concepts used

- Custom type definition (`type MyInt int`)
- Empty interface alias `any`
- Type assertion syntax `r.(MyInt)`
- Safe assertion with comma-ok idiom (`val, ok := r.(Type)`)

## How it works

1. Declares custom type `MyInt int` and initializes `var m MyInt = 10`.
2. Stores `m` inside interface variable `r any`.
3. Performs type assertion `i, ok := r.(MyInt)`. Because `r` holds `MyInt`, `ok` is `true` and `i` has type `MyInt`.
4. Tests assertion against `string` and `int`, both yielding `ok == false` because the underlying type is strictly `MyInt`, not primitive `int`.

## Key excerpt

```go
type MyInt int

func main() {
	var r any
	var m MyInt = 10

	r = m

	i, ok := r.(MyInt)
	fmt.Println(i + 10)

	_, ok = r.(string)
	_, ok = r.(int)
}
```

## Expected behavior (from reading the code, not run)

- Prints `20` (`10 + 10`).
- Assertion `r.(int)` yields `ok = false` because in Go, `MyInt` is a distinct defined type from `int`.

## Things to watch

- Single-value type assertion `r.(string)` without comma-ok triggers a runtime panic if the dynamic type does not match. Always use `val, ok := r.(Type)` for uncertain types.

## Terms

- **Type assertion**: An operation that provides access to an interface's underlying concrete value of a specified type.
- **Comma-ok idiom**: A two-value assignment returning the converted value and a boolean success indicator.
