## Overview

This program demonstrates escape analysis in Go, highlighting how passing local stack variables to functions accepting empty interfaces (such as `fmt.Println`) causes variables to escape to the heap.

## Concepts used

- Escape analysis (`go build -gcflags="-m"`)

## How it works

1. Defines a package-level global variable `var a = 10`.
2. Defines `add(x, y int) int` where `z := x + y`.
3. Demonstrates that uncommenting `fmt.Println(z)` boxes `z` into `any`, forcing `z` to escape to the heap.
4. Without `fmt.Println(z)`, `z` remains purely on the stack.

## Key excerpt

```go
var a = 10

func add(x, y int) int {
	z := x + y
	// fmt.Println(z) // z escapes to heap, because of Println()
	return z
}

func main() {
	add(2, 4)
	add(a, 5)
}
```

## Things to watch

- `fmt.Println` takes variadic `...any`. Boxing primitive types into interface wrappers forces runtime heap allocations unless the compiler can prove lifetime boundedness.

## Terms

- **Escape analysis**: A compiler optimization phase determining whether variable storage can remain on the stack or must be allocated on the heap.
- **Interface boxing**: Wrapping a concrete value into an interface header, often requiring a heap allocation to store the value.
