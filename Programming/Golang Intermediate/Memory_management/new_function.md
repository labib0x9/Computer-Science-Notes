## Overview

This program demonstrates that calling Go's built-in `new()` function does not guarantee heap allocation; the compiler places the allocated object on the stack if it does not escape the function scope.

## How it works

1. `EscapeToHeap()` allocates `n := new(int)` and passes `n` to `fmt.Println(n)`. Because `fmt.Println` accepts `any`, `n` escapes to the heap.
2. `NoEscapeToHeap()` allocates `m := new(int)` and suppresses unused warnings with `_ = m`. Because `m` never leaves local scope, the compiler allocates it on the stack.

## Key excerpt

```go
func EscapeToHeap() {
	n := new(int)
	fmt.Println(n) // escape to heap
}

func NoEscapeToHeap() {
	m := new(int)
	_ = m // stays on stack
}

func main() {
	EscapeToHeap()
	NoEscapeToHeap()
}
```

## Expected behavior (from reading the code, not run)

- Prints the pointer memory address of `n` inside `EscapeToHeap()`.
- `NoEscapeToHeap()` executes with zero heap allocations.

## Things to watch

- Unlike C++ where `new` always allocates on the free store (heap), Go's `new()` is an allocation expression whose location (stack vs heap) is decided solely by escape analysis.

## Terms

- **new()**: Built-in function that allocates zeroed memory for a type `T` and returns a pointer `*T`.
- **Stack allocation**: Blazing-fast memory allocation reclaimed automatically when the stack frame returns.
