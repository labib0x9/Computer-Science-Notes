## How it works

1. Prepares a slice of string tokens.
2. Measures allocations for naive loop concatenation `out += w`, which reallocates new string buffers on every iteration.
3. Measures allocations for `strings.Builder` pre-sized with `sb.Grow(100)` and `sb.WriteString(w)`.
4. Prints the allocation counts of both strategies for comparison.

## Key excerpt

```go
allocCount := testing.AllocsPerRun(1000, func() {
	out := ""
	for _, w := range words {
		out += w
	}
})
fmt.Println("Allocations using += :", allocCount)

allocCount = testing.AllocsPerRun(1000, func() {
	var sb strings.Builder
	sb.Grow(100) // preallocate enough capacity
	for _, w := range words {
		sb.WriteString(w)
	}
	_ = sb.String()
})
fmt.Println("Allocations using strings.Builder :", allocCount)
```

## Expected behavior (from reading the code, not run)

- Prints a high allocation count for `+=` (multiple allocations per iteration).
- Prints a drastically lower or zero allocation count for `strings.Builder` with `Grow`.

## Things to watch

- `testing.AllocsPerRun` runs warm-up iterations before averaging allocations over the specified run count (1000 iterations).

## Terms

- **AllocsPerRun**: Standard library testing utility calculating the average number of heap allocations per iteration of a function.
- **strings.Builder**: High-efficiency string accumulator minimizing memory copying by maintaining an internal byte slice.
