## Overview

This program explores slice memory reuse by monitoring length and capacity progression during appending, then demonstrating how reslicing to zero (`sl = sl[:0]`) retains capacity without reallocation.

## Concepts used

- Slice length (`len`) vs capacity (`cap`)
- Amortized geometric capacity expansion
- Slice buffer reuse with `sl[:0]`

## How it works

1. Initializes an empty slice `sl := make([]int, 0)`.
2. Appends 20 integers in a loop, observing capacity jump from 0 to 32.
3. Reslices `sl = sl[:0]`, resetting `len` to 0 while keeping `cap` at 32.
4. Subsequent appends into `sl` reuse the already-allocated memory buffer without triggering new heap allocations.

## Key excerpt

```go
sl := make([]int, 0)
check(sl) // len: 0, cap: 0

for i := 0; i < 20; i++ {
	sl = append(sl, i)
}
check(sl) // len: 20, cap: 32

// Reuse capacity without allocating new backing memory:
sl = sl[:0]
check(sl) // len: 0, cap: 32
```

## Things to watch

- Reslicing to zero retains references to underlying objects in the backing array. If elements are pointers, nil them out first to prevent memory leaks from retained references.

## Terms

- **Capacity**: The maximum number of elements a slice can hold before needing to reallocate its underlying backing array.
- **Zero-allocation reuse**: Reusing already allocated memory buffers to avoid garbage collection pressure.
