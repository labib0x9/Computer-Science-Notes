This program demonstrates compiler escape analysis diagnostics on string concatenation loops, highlighting why repeated string addition moves accumulator strings and loop variables onto the heap.

3. Demonstrates compiler output comments showing `./main.go: moved to heap: out` and `moved to heap: w`.

## Key excerpt

```go
words := []string{"Hello", "world", "
", "I", "am", "learning", "goooooooooooooooooooooooo"}

out := ""

ptr := unsafe.Pointer(&out)
fmt.Println("Allocation at:", ptr)

for _, w := range words {
	out += w
}
```

## Expected behavior (from reading the code, not run)

- Prints the address of `out`.
- Executing `go build -gcflags="-m"` prints compiler escape decisions showing `moved to heap`.

## Things to watch

- In loops with many iterations, naive string addition (`+=`) creates $O(N^2)$ memory copying overhead. Use `strings.Builder` or `bytes.Buffer` instead.

## Terms

- **Moved to heap**: Compiler escape analysis decision indicating a variable cannot safely live on the stack and must be allocated dynamically.
- **GC pressure**: The frequency and workload imposed on the Go garbage collector by rapid transient heap allocations.
