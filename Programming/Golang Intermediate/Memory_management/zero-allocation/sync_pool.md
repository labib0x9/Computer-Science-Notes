## How it works

1. Custom `Buffer []byte` type defines `Append(s string)` and `Truncate()` to reset its length to zero.
2. `bufPool := sync.Pool{ New: func() any { return new(Buffer) } }` defines the allocation factory when the pool is depleted.
3. Code borrows a buffer via `buf := bufPool.Get().(*Buffer)`.
4. Appends data and uses the buffer.
5. Cleans the buffer with `buf.Truncate()` and returns it to the pool via `bufPool.Put(buf)`.

## Key excerpt

```go
type Buffer []byte

func (b *Buffer) Append(s string) {
	*b = append(*b, s...)
}

func (b *Buffer) Truncate() {
	*b = (*b)[0:0]
}

var bufPool = sync.Pool{
	New: func() any {
		return new(Buffer)
	},
}
```

## Expected behavior (from reading the code, not run)

- Borrows buffers from `sync.Pool`, appends messages, and recycles them without triggering continuous allocations.
- Subsequent `Get()` calls retrieve recycled buffers without invoking `New`.

## Things to watch

- Always reset/clear objects before returning them to `sync.Pool` to prevent data leakage between distinct consumers.
- Items in `sync.Pool` may be evicted and reclaimed by the garbage collector at any GC cycle.

## Terms

- **sync.Pool**: A concurrent-safe set of temporary objects that can be saved and retrieved individually.
- **Object pooling**: A creational design pattern that reuses objects from a pre-allocated pool rather than creating and destroying them.
