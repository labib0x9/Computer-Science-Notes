## Overview

This program demonstrates how Go's reflection subsystem inspects pointer types at runtime, contrasting the pointer's own type descriptor with the underlying element type it references.

[basic.go](https://github.com/labib0x9/Programming-Notes/blob/main/Programming/Golang%20Intermediate/Pointer/basic.go)

## Concepts used

- Pointer declaration and address-of operator (`&x`)
- Type reflection using `reflect.TypeOf`
- Inspecting pointer kind (`reflect.Ptr`) and dereferencing with `.Elem()`

## How it works

1. Declares an integer `x` and creates pointer `p := &x`.
2. Inspects `p` with `t := reflect.TypeOf(p)`.
3. Demonstrates `t` is `*int`, `t.Kind()` is `reflect.Ptr`, and `t.Elem().Kind()` reveals the pointed-to type `reflect.Int`.

## Key excerpt

```go
var x int
p := &x
t := reflect.TypeOf(p)

fmt.Println(t)               // *int
fmt.Println(t.Kind())        // ptr
fmt.Println(t.Elem().Kind()) // int
```

## Expected behavior (from reading the code, not run)

- Prints `*int`
- Prints `ptr`
- Prints `int`

## Things to watch

- Calling `.Elem()` on a non-pointer or non-container reflection type causes a runtime panic.

## Terms

- **Pointer**: A variable that stores the memory address of another variable.
- **Elem**: Reflection method on pointers, interfaces, slices, and maps returning the contained element type.
