## How it works

1. Defines `Header` struct containing three 2-byte fields (`src uint16`, `dst uint16`, `tmp uint16`).
2. Populates a 6-byte slice `data := []byte{0x12, 0x34, 0x34, 0x12, 0x52, 0x18}`.
3. Reinterprets the byte array as a `*Header` pointer via `(*Header)(unsafe.Pointer(&data[0]))`.
4. Observes how little-endian byte ordering swaps byte pairs into integer values.

## Key excerpt

```go
type Header struct {
	src uint16 // 2bytes
	dst uint16 // 2bytes
	tmp uint16 // 2bytes
}

data := []byte{
	0x12, 0x34,
	0x34, 0x12,
	0x52, 0x18,
}

hdr := (*Header)(unsafe.Pointer(&data[0]))
fmt.Printf("src: 0x%x, dst: 0x%x\n", hdr.src, hdr.dst)
```

## Expected behavior (from reading the code, not run)

- On little-endian architectures (x86_64, ARM64), `0x12, 0x34` is read with least significant byte first, yielding `0x3412` (13330 decimal).

## Things to watch

- Endianness sensitivity: casting memory directly produces architecture-dependent numbers. In network protocols, `encoding/binary.BigEndian` is preferred for portability.

## Terms

- **Endianness**: The order in which sequence of bytes are stored in computer memory (Little-Endian: least significant byte first; Big-Endian: most significant byte first).
- **Type casting via unsafe**: Reinterpreting raw memory addresses as typed struct pointers.
