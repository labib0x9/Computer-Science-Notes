## Overview

This program demonstrates zero-copy file I/O in Go by mapping a file directly into process virtual memory using the Unix `syscall.Mmap` system call, allowing file bytes to be read and written like an in-memory slice.

## Source

[mmap.go](https://github.com/labib0x9/Programming-Notes/blob/main/Programming/Golang%20Intermediate/Pointer/memory%20mapper/mmap.go)

## Concepts used

- File descriptor retrieval via `f.Fd()`
- Unix `syscall.Mmap` system call (`PROT_READ`, `PROT_WRITE`, `MAP_SHARED`)
- Virtual memory pages and `syscall.Munmap` cleanup

## How it works

1. Opens a file `test.txt` with read-write permissions (`os.O_RDWR`).
2. Obtains file size using `f.Stat()`.
3. Invokes `syscall.Mmap(int(f.Fd()), 0, int(size), syscall.PROT_READ|syscall.PROT_WRITE, syscall.MAP_SHARED)`.
4. Returns a byte slice `mmapData []byte` that maps directly onto the OS page cache for the file.
5. Reading or modifying `mmapData` directly accesses and updates the underlying file without `read()` or `write()` syscall overhead.

## Key excerpt

```go
f, err := os.OpenFile(filename, os.O_RDWR, 0)
if err != nil {
	panic(err)
}
defer f.Close()

fi, _ := f.Stat()
data, err := syscall.Mmap(int(f.Fd()), 0, int(fi.Size()),
	syscall.PROT_READ|syscall.PROT_WRITE, syscall.MAP_SHARED)
if err != nil {
	panic(err)
}
defer syscall.Munmap(data)

fmt.Println(string(data))
```

## Expected behavior (from reading the code, not run)

- Reads and prints the text contents of `test.txt` directly from mapped memory.
- Any modifications made to `data` are reflected back into `test.txt`.

## Things to watch

- Always unmap mapped buffers using `syscall.Munmap` when done.
- If another process truncates the underlying file while mapped, accessing the slice triggers a fatal `SIGBUS` operating system crash.

## Terms

- **mmap**: POSIX system call that maps files or devices into memory.
- **Page cache**: Operating system memory cache holding pages read from disk storage.
