## Overview

This program visually demonstrates parameter passing in Go by comparing memory addresses using `unsafe.Pointer`, showing that pass-by-value copies struct memory while pass-by-pointer forwards the original address.

## Concepts used

## How it works

1. Struct `A` contains fields `v1 int` and `v2 string`.
2. `PassByValue(v A)` receives a duplicate copy of `A`; taking `&v` prints a local stack address distinct from the caller's struct.
3. `PassByReference(v *A)` receives the memory address directly; printing `unsafe.Pointer(v)` matches the caller's original address.

## Key excerpt

```go
type A struct {
	v1 int
	v2 string
}

func PassByValue(v A) {
	ptr := unsafe.Pointer(&v)
	fmt.Println("PassByValue=", ptr)
}

func PassByReference(v *A) {
	ptr := unsafe.Pointer(v)
	fmt.Println("PassByReference=", ptr)
}
```

## Expected behavior (from reading the code, not run)

- Calling `PassByValue` prints a distinct local address representing the stack-copied struct.
- Calling `PassByReference` prints the identical pointer address allocated in `main`.

## Things to watch

- Go is strictly pass-by-value. Even when passing pointers, the pointer value (the 8-byte memory address) is itself copied into the function parameter.

## Terms

- **Pass by value**: Parameter passing mechanism where a copy of the actual argument value is supplied to the function.
- **Pass by pointer**: Passing the memory address of an object so changes reflect back onto the caller's state.
