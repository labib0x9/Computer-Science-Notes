## How it works

1. Declares struct `s` with `f float32` (4 bytes) and `x int` (8 bytes on 64-bit).
2. Because 8-byte integers must align on 8-byte boundaries, the compiler inserts 4 padding bytes following `f`.
3. Total struct size becomes 16 bytes rather than 12 bytes.
4. Compares `unsafe.Pointer(&v.x)` with computed pointer `unsafe.Pointer(uintptr(vPtr) + unsafe.Offsetof(v.x))`.

## Key excerpt

```go
type s struct {
	f float32 // 4 + padding(4) = 8 bytes
	x int     // 8 bytes
}

v := s{3.1416, 2}

vPtr := unsafe.Pointer(&v)
fPtr := unsafe.Pointer(&v.f)
xPtr := unsafe.Pointer(&v.x)

fmt.Println("Struct size:", unsafe.Sizeof(v)) // 16 bytes
fmt.Println("Offset of x:", unsafe.Offsetof(v.x)) // 8
```

## Things to watch

- Struct field ordering matters: arranging fields from largest to smallest minimizes padding waste and reduces overall struct size.

## Terms

- **Alignment**: The requirement that an $N$-byte value must reside at a memory address that is a multiple of $N$.
- **Padding**: Unused bytes inserted by the compiler between struct fields to satisfy alignment rules.
