## Overview

This program investigates the low-level memory representation of Go slices, distinguishing between the 24-byte stack-allocated slice header and the heap-allocated underlying backing array.

## Concepts used

- Slice headers (data pointer, length, capacity)
- Package `unsafe` (`unsafe.Pointer`, `unsafe.Sizeof`)
- Distinguishing stack slice header address from backing array address

## How it works

1. Allocates `sl := make([]int, 10, 20)`.
2. Inspects `unsafe.Pointer(&sl)`: represents the memory address of the 24-byte slice header.
3. Inspects `unsafe.Pointer(&sl[0])`: represents the memory address of element 0 in the heap-backed array.
4. Confirms `unsafe.Sizeof(sl)` is 24 bytes on 64-bit platforms (three 8-byte words: pointer, int len, int cap).

## Key excerpt

```go
sl := make([]int, 10, 20)

ptr := unsafe.Pointer(&sl) // memory of slice header - e.g. 0x1400000c018
fmt.Println(ptr)

ptr = unsafe.Pointer(&sl[0]) // memory of backed-array - e.g. 0x14000106000
fmt.Println(ptr)

sliceHeaderSize := unsafe.Sizeof(sl) // 24-bytes
fmt.Println(sliceHeaderSize)
```

## Expected behavior (from reading the code, not run)

- Prints two distinct hexadecimal addresses: one for the local slice header and one for the backing array.
- Prints `24` for `unsafe.Sizeof(sl)`.

## Things to watch

- Slices are not arrays; a slice is a lightweight 3-word descriptor pointing to an array.
- Passing a slice by value passes a copy of the 24-byte header, while both headers still reference the same backing storage.

## Terms

- **Slice header**: The 3-field descriptor comprising `Data unsafe.Pointer`, `Len int`, and `Cap int`.
- **Backing array**: The contiguous memory block where slice elements actually reside.
