## Overview

This program traces the memory mechanics of Go's built-in `append()` function, illustrating how exceeding capacity forces reallocation to a new, larger backing array on the heap.

## Concepts used

- Slice capacity exhaustion and geometric growth
- `unsafe.SliceData` to obtain direct backing array pointers
- Slice header preservation vs backing storage relocation

## How it works

1. Creates `s := make([]int, 1)` with length 1 and capacity 1.
2. Observes the slice header address and initial backing array pointer via `unsafe.SliceData(s)`.
3. Appends an element: `s = append(s, 10)`. Because capacity was 1, Go allocates a new larger backing array and copies existing elements.
4. Compares old and new pointers to show the backing array relocation.

## Key excerpt

```go
s := make([]int, 1)

// slice-header on stack
ptr := unsafe.Pointer(&s)
fmt.Println("Slice Header:", ptr)

// Backed-array on heap
bPtr := unsafe.SliceData(s)
fmt.Println("First Elem  :", bPtr)

s = append(s, 10)
fmt.Println("After Append:", unsafe.SliceData(s))
```

## Expected behavior (from reading the code, not run)

- Prints the address of the slice header (which remains at the same local stack location).
- Prints the initial backing array address.
- Following `append`, prints a brand new backing array address, demonstrating reallocation.

## Things to watch

- Always reassign the result of `append` back to the slice variable (`s = append(s, val)`), because reallocation produces an updated slice header.

## Terms

- **Reallocation**: Allocating a new memory buffer when the existing storage is insufficient to hold new data.
- **SliceData**: Built-in `unsafe.SliceData(s)` function returning a pointer to the first element of slice `s`.
