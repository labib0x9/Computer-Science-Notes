## Overview

This program demonstrates how Go's string immutability guarantee can be broken at runtime using the `unsafe` package by casting a heap-backed string's data pointer into a mutable byte slice.

## How it works

1. Allocates a string on the heap: `s := string([]byte("hello"))`. (A string literal `s := "hello"` resides in read-only memory and attempting mutation crashes with `SIGBUS`/`SIGSEGV`).
2. Retrieves raw pointer to underlying bytes via `sPtr := unsafe.StringData(s)`.
3. Converts the raw pointer into a mutable byte slice `b := unsafe.Slice(sPtr, len(s))`.
4. Overwrites `b[0] = 'H'`, mutating the content of `s` directly without reallocation.

## Key excerpt

```go
// s := "hello" // read-only memory, causes SIGBUS/SIGSEGV on write
s := string([]byte("hello")) // heap-allocated

sPtr := unsafe.StringData(s) // pointer to backing array of s
b := unsafe.Slice(sPtr, len(s))

b[0] = 'H' // modifies s in place
fmt.Println(s) // prints "Hello"
```

## Expected behavior (from reading the code, not run)

- Prints the pointer addresses of the backing bytes.
- Mutating `b[0]` modifies `s`, causing subsequent printing of `s` to show `"Hello"` instead of `"hello"`.

## Things to watch

- Severe safety hazard: Go compilers and the runtime assume strings are immutable. Mutating string backing memory leads to data races, corrupt map keys, and undefined behavior.

## Terms

- **String immutability**: Language rule stipulating that string contents cannot be changed after creation.
- **SIGSEGV / SIGBUS**: Fatal operating system signals raised when writing to protected read-only memory pages.
