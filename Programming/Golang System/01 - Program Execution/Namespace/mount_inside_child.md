## Overview

This program represents an experimental Linux systems programming exercise exploring container namespace manipulation. It spawns a child shell inside a new mount namespace (`CLONE_NEWNS`), reads the child's mount namespace ID from `/proc/<pid>/ns/mnt`, and attempts to switch the calling host thread into the child's namespace using the `setns` system call to create a private `tmpfs` directory before rolling back.

## How it works

The code contains `//go:build linux`.

In `main`:
- Calls `runtime.LockOSThread()` to pin the executing goroutine to a single OS thread. This is mandatory because Linux namespaces are per-thread attributes.
- Opens the parent process's own mount namespace file descriptor at `/proc/self/ns/mnt` for later rollback.
- Spawns `cmd1 := exec.Command("sh")` with `Cloneflags: syscall.CLONE_NEWNS`.
- Retrieves `childPID := cmd1.Process.Pid`.
- Resolves the symlink `/proc/<childPID>/ns/mnt` via `os.Readlink` to extract the numerical mount namespace ID (e.g. `mnt:[4026532250]`).
- Opens `/proc/<childPID>/ns/mnt` to obtain a file descriptor for the child's namespace.
- Invokes `unix.Setns(int(childNS.Fd()), unix.CLONE_NEWNS)` to join the child's mount namespace. (The code notes that this panics with `invalid argument`).
- Creates a directory `/tmp/tmp_<mntID>` and mounts a private `tmpfs` onto it.
- Restores the host thread back to the parent namespace using `unix.Setns(int(parentNs.Fd()), unix.CLONE_NEWNS)`.
- Waits for `cmd1.Wait()` and removes the temporary directory during cleanup.

## Key excerpt

```go
	// For OS Thread Locking
	runtime.LockOSThread()
	defer runtime.UnlockOSThread()

	// Read parent mnt namespace
	parentNs, err := os.Open("/proc/self/ns/mnt")
	if err != nil {
		panic(err)
	}
	defer parentNs.Close()

	cmd1 := exec.Command("sh")
	cmd1.SysProcAttr = &syscall.SysProcAttr{
		Cloneflags: syscall.CLONE_NEWNS,
	}

	if err := cmd1.Start(); err != nil {
		panic(err)
	}

	childPID := cmd1.Process.Pid
	mntNSPath := fmt.Sprintf("/proc/%d/ns/mnt", childPID)

	childNS, err := os.Open(mntNSPath)
	if err != nil {
		panic(err)
	}
	defer childNS.Close()

	// # panic: invalid argument
	if err := unix.Setns(int(childNS.Fd()), unix.CLONE_NEWNS); err != nil {
		panic(err)
	}
```

## Expected behavior (from reading the code, not run)

To compile and run on Linux:
```bash
sudo go run mount_inside_child.go
```
Expected behavior:
The program panics at line 66 with `panic: invalid argument` (EINVAL). In Linux, calling `setns` with `CLONE_NEWNS` requires that the calling process not share filesystem attributes (`CLONE_FS`) with multi-threaded environments, which conflicts with Go's multi-threaded runtime unless initialized before the Go runtime spawns threads via Cgo constructor.

## Things to watch

- **Known failure / experiment status:** As explicitly commented by the author (`// NOT WORKING...` and `// # panic: invalid argument`), this program is an experimental exploration of `setns`. In Go, switching mount namespaces in a running multi-threaded process is restricted by the Linux kernel.
- **Privilege requirement:** Modifying namespaces and mounting filesystems requires `CAP_SYS_ADMIN` root privileges.

## Terms

- **setns:** A Linux system call allowing a process or thread to attach to an existing namespace via a file descriptor.
- **runtime.LockOSThread:** Binds the calling goroutine to its current OS thread until `UnlockOSThread` is called.
