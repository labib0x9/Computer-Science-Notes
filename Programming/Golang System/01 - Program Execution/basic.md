## Overview

This program demonstrates how to execute external programs in Go using the `os/exec` package. It showcases binding input and output streams using `strings.NewReader` and `strings.Builder`, runs an executable, and demonstrates an important Go runtime rule: an `exec.Cmd` instance cannot be reused for a second execution once started.

## Concepts used

- Process creation with `exec.Command`
- Stream redirection with `io.Reader` and `io.Writer` interfaces

- Non-reusability of `exec.Cmd` structs

## How it works

The `main` function executes the following sequence:
- Prepares a command `cmd := exec.Command("./sum")`.
- Sets up an output buffer `out := strings.Builder{}` and an input stream `in := strings.NewReader("1 2\n")`.
- Binds standard input and standard output: `cmd.Stdout = &out; cmd.Stdin = in;`.
- Calls `cmd.Run()`, which internally combines `cmd.Start()` and `cmd.Wait()`. It blocks until the process finishes and outputs the result.
- Resets the output buffer with `out.Reset()`.
- Attempts to call `cmd.Start()` again on the exact same `cmd` instance. Because Go explicitly marks `cmd` as started internally, calling `Start()` a second time returns an error (`"exec: already started"`).
- Calls `cmd.Wait()` and logs any error.

## Things to watch

- **Non-reusable exec.Cmd:** Once `Start()` or `Run()` is invoked on an `exec.Cmd`, that struct instance cannot be run again. To run the same command multiple times, construct a new `exec.Command` instance for each invocation.
- **Dependency on local binary:** The command expects a compiled binary `./sum` in the current working directory. If missing, `cmd.Run()` fails with `exec: "./sum": stat ./sum: no such file or directory`.

## Terms

- **exec.Cmd:** A Go struct representing an external command being prepared or run.
- **Run vs. Start:** `Run` starts the process and waits for completion; `Start` starts the process asynchronously without waiting.
