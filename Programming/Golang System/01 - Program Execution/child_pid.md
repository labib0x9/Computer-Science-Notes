## Overview

This program demonstrates how to retrieve and inspect process IDs (PIDs) for both the parent Go process and a newly spawned child process using the `os` and `os/exec` packages. Obtaining the child PID is necessary for monitoring process trees, transmitting operating system signals, or tracking background tasks.

## Concepts used

- Process ID management (`os.Getpid()`)
- Asynchronous process spawning via `cmd.Start()`
- Child process inspection through `cmd.Process.Pid`
- Waiting for process termination with `cmd.Wait()`

## How it works

The `main` function executes the following:
- Creates a command `cmd := exec.Command("./sum")`.
- Attaches standard streams (`os.Stdin`, `os.Stdout`, `os.Stderr`).
- Prints the parent process ID by calling `os.Getpid()`.
- Invokes `cmd.Start()`. Unlike `cmd.Run()`, which blocks until exit, `cmd.Start()` forks and executes the process in the background and returns immediately once the operating system assigns a process structure.
- Accesses `cmd.Process.Pid` and prints the child PID.
- Invokes `cmd.Wait()` to wait for the child process to complete and avoid creating a zombie process.

## Key excerpt

```go
	// Parent PID
	fmt.Println("Parent PID=", os.Getpid())

	if err := cmd.Start(); err != nil {
		fmt.Println("Start error:" + err.Error())
		return
	}

	// Child PID
	fmt.Println("Child PID=", cmd.Process.Pid)

	if err := cmd.Wait(); err != nil {
		fmt.Println("Wait error:" + err.Error())
		return
	}
```

## Things to watch

- **cmd.Process availability:** The `cmd.Process` pointer and its `Pid` field are only populated *after* `cmd.Start()` or `cmd.Run()` succeeds. Accessing `cmd.Process` before starting results in a `nil` pointer dereference panic.
- **Zombie processes:** Every process started with `cmd.Start()` must eventually be waited on with `cmd.Wait()` so the operating system can release the process table entry upon termination.

## Terms

- **PID (Process ID):** A unique numerical identifier assigned by the operating system kernel to each active process.
- **Zombie Process:** A terminated child process whose exit status has not yet been read by its parent via `wait`.
