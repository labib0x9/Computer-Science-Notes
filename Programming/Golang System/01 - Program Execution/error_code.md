## Overview

This program demonstrates how to inspect process execution errors and retrieve numerical exit codes when external commands fail in Go. When an external process exits with a non-zero status code, `os/exec` returns an error that wraps `*exec.ExitError`, allowing developers to extract the exact integer exit code.

## Concepts used

- Executing shell commands (`sh -c pwd`)
- Error type assertion (`err.(*exec.ExitError)`)
- Numeric process exit codes (`ExitCode()`)

## How it works

The `main` function executes:
- Prepares command `cmd := exec.Command("sh", "-c", "pwd")`.
- Binds standard output and standard error to `os.Stdout` and `os.Stderr`.
- Calls `cmd.Run()`: this spawns the shell, prints the current working directory, and waits for completion.
- Evaluates `cmd.Wait()`: checks if the return error is an instance of `*exec.ExitError` using a type assertion `errExit, ok := err.(*exec.ExitError)`. If true, prints `errExit.ExitCode()`.

## Key excerpt

```go
	if err := cmd.Run(); err != nil {
		fmt.Println("Run error:" + err.Error())
		return
	}

	// Handle error code
	err := cmd.Wait()
	if errExit, ok := err.(*exec.ExitError); ok {
		fmt.Println("Wait error:" + err.Error())
		fmt.Println("Exit Code:", errExit.ExitCode())
		return
	}
```

## Things to watch

- **Redundant cmd.Wait() after cmd.Run():** `cmd.Run()` internally executes `cmd.Start()` followed immediately by `cmd.Wait()`. Calling `cmd.Wait()` again on line 29 will return an error saying `exec: Wait was already called`. To inspect exit codes properly after `cmd.Run()`, inspect the error returned directly by `cmd.Run()`.

## Terms

- **Exit Code:** An integer value returned by an executable upon termination, where 0 conventionally indicates success and non-zero values indicate error states.
- **Type assertion:** A Go syntax construct (`x.(T)`) that checks whether an interface value holds a specific concrete type.
