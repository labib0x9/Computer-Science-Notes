## Overview

This program demonstrates how a parent process can transfer controlling terminal ownership to a child process group using the `TIOCSPGRP` ioctl on Linux. It demonstrates why ignoring the `SIGTTOU` signal is necessary when modifying terminal settings from a background group, and shows how to restore terminal ownership to the parent once the child exits.

## How it works

The code specifies `//go:build linux`.

In `main`:
- Spawns child `./sum` with `Setpgid: true` so the child receives its own process group.
- Opens the controlling terminal device `/dev/tty` with read/write access.
- Retrieves the child process group ID `childPGID`.
- Invokes `unix.IoctlSetPointerInt(int(tty.Fd()), unix.TIOCSPGRP, childPGID)` to transfer foreground terminal control to the child.
- Calls `cmd1.Wait()`, allowing the child to read and write to the terminal interactively without receiving `SIGTTIN`.
- After the child terminates, retrieves `parentPGID` via `syscall.Getpgrp()` and executes `unix.IoctlSetPointerInt(..., unix.TIOCSPGRP, parentPGID)` to restore the parent process as the foreground terminal group.
- Inspects exit status.

Because the `signal.Ignore(syscall.SIGTTOU)` call is commented out, when the parent process calls `TIOCSPGRP` while not in the foreground, the kernel may generate a `SIGTTOU` signal, which can halt the process unless `SIGTTOU` is ignored or handled.

## Things to watch

- **The necessity of ignoring SIGTTOU:** When a process attempts to change the terminal's foreground process group using `TIOCSPGRP` or `tcsetpgrp()`, the POSIX standard requires the kernel to generate `SIGTTOU`. If `SIGTTOU` is not explicitly ignored with `signal.Ignore(syscall.SIGTTOU)`, the calling process will be stopped immediately by the operating system.

## Terms

- **TIOCSPGRP:** An ioctl request constant that sets the foreground process group ID of the controlling terminal.
- **SIGTTOU:** A signal sent to a background process when it attempts to write to the terminal or alter terminal settings.
