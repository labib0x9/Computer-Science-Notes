## Overview

This program demonstrates a subtle terminal management bug in Linux systems programming. A parent process spawns a child in a new process group, hands foreground terminal ownership to the child using `TIOCSPGRP`, waits for the child to finish, but fails to reclaim terminal ownership back to itself before attempting to read from standard input.

## Concepts used

- Process group assignment (`Setpgid: true`)
- Foreground transfer with `TIOCSPGRP`
- The `SIGTTIN` signal generated on un-reclaimed terminals
- Terminal line buffered reading with `bufio.Reader`

## How it works

The program includes `//go:build linux`.

In `main`:
- Spawns `./sum` with `Setpgid: true`.
- Opens `/dev/tty` and moves the child process group to the foreground using `unix.IoctlSetPointerInt(..., unix.TIOCSPGRP, childPGID)`.
- Waits for child termination: `err = cmd1.Wait()`.
- Evaluates exit error.
- Immediately attempts to read from standard input: `reader := bufio.NewReader(os.Stdin); reader.ReadString('\n')`.
- Because terminal ownership was given to the child and never restored back to the parent, the terminal's foreground group remains set to the deceased child's PGID. As a result, the parent is now in a background group; calling `ReadString` triggers `SIGTTIN` from the kernel, suspending the parent process.

## Things to watch

- **Missing terminal reclaim:** Whenever `TIOCSPGRP` is called to give foreground status to a child, the parent must restore itself as the foreground group using `unix.IoctlSetPointerInt(int(tty.Fd()), unix.TIOCSPGRP, syscall.Getpgrp())` before performing any subsequent reads on standard input.

## Terms

- **Controlling Terminal:** The terminal device (such as `/dev/tty`) associated with a session and its process groups.
- **Job Control:** The capability of an operating system shell to suspend, resume, and multiplex terminal access across multiple process groups.
