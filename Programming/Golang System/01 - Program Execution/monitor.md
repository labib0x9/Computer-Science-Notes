## Overview

This program demonstrates how to launch a child server process asynchronously using `cmd.Start()` in Go, log its Process ID (PID), and wait for its completion. It is designed as a harness for observing resource utilization (memory RSS, virtual memory VSZ, CPU percentage) and open file descriptors via terminal utilities like `ps` and `lsof`.

## Concepts used

## How it works

The `main` function executes:
- Prepares command `cmd := exec.Command("./server")`.
- Maps standard input, output, and error streams.
- Calls `cmd.Start()`. This forks and runs the `./server` binary in the background and returns immediately without blocking.
- Prints `PID= <cmd.Process.Pid>`.
- Calls `cmd.Wait()` to block until the server exits, avoiding zombie processes.
- Inspects and prints exit status.

## Key excerpt

```go
func main() {

	cmd := exec.Command("./server")
	cmd.Stdin = os.Stdin
	cmd.Stdout = os.Stdout
	cmd.Stderr = os.Stderr

	if err := cmd.Start(); err != nil {
		panic(err)
	}

	fmt.Println("PID=", cmd.Process.Pid)

	err := cmd.Wait()
	if errExit, ok := err.(*exec.ExitError); ok {
		fmt.Println("Run Error=", err.Error())
		fmt.Println("Exit Error=", errExit.ExitCode())
		return
	}

	fmt.Println("Succesfully terminated")
}
```

## Things to watch

- **Dependency on ./server:** If `./server` is missing or not marked as executable, `cmd.Start()` will panic with `exec: "./server": stat ./server: no such file or directory`.

## Terms

- **RSS (Resident Set Size):** The portion of memory occupied by a process held in physical RAM.
- **VSZ (Virtual Memory Size):** The total amount of virtual memory allocated to a process.
- **lsof:** A Unix diagnostic tool that lists information about files opened by processes.
