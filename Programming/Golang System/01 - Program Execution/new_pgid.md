## Overview

This program demonstrates the difference between executing a child process within the parent's process group versus assigning the child its own isolated process group (`Setpgid: true`) in Go. In POSIX operating systems, process groups dictate signal broadcast domains (such as `SIGINT` and `SIGTERM`).

## How it works

In `main`:
- Case 1: Shared Process Group
  - Spawns `./sum` without `SysProcAttr`.
  - The child inherits the parent's PGID (`Parent PGID == Child PGID`).
  - Sending a termination signal (such as `Ctrl+C` or `SIGINT` to the process group) kills both parent and child simultaneously.
  - Waits for completion.
- Case 2: Isolated Process Group
  - Spawns `./sum` with `cmd1.SysProcAttr = &syscall.SysProcAttr{Setpgid: true}`.
  - The kernel assigns a new process group to the child where `Child PGID == Child PID`.
  - Sending a signal to the parent's process group does not affect the child, and vice versa.
  - Waits for completion.

## Key excerpt

```go
	// Case 1: Shared PGID
	cmd := exec.Command("./sum")
	cmd.Stdin = os.Stdin
	cmd.Stdout = os.Stdout
	cmd.Stderr = os.Stderr

	if err := cmd.Start(); err != nil {
		panic(err)
	}

	// Case 2: Isolated PGID
	cmd1 := exec.Command("./sum")
	cmd1.Stdin = os.Stdin
	cmd1.Stdout = os.Stdout
	cmd1.Stderr = os.Stderr

	cmd1.SysProcAttr = &syscall.SysProcAttr{
		Setpgid: true,
	}

	if err := cmd1.Start(); err != nil {
		panic(err)
	}
```

## Things to watch

- **Orphan processes on parent kill:** In Case 2, if the parent process is killed, the child in the separate process group continues running in the background as an orphan (reparented to `init` or `systemd`).

## Terms

- **Signal Domain:** The boundary of processes that receive a signal when directed to a process group ID instead of a single process ID.
- **Orphan Process:** A running process whose parent has terminated.
