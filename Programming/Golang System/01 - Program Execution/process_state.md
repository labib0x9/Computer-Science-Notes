## Overview

This program demonstrates how to inspect detailed operating system process metadata and execution metrics using `cmd.ProcessState` in Go on Linux. It shows that `ProcessState` is `nil` while a process is running and becomes populated only after `cmd.Wait()` finishes, exposing CPU usage, execution times, and exit statuses.

## Concepts used

- Process lifecycle tracking with `cmd.ProcessState`
- User CPU time and System kernel CPU time inspection
- Querying exit codes and termination flags
- Operating system resource accounting (`SysUsage()`)

## How it works

The code contains `//go:build linux`.

In `main`:
- Prepares `cmd1 := exec.Command("./sum")`.
- Starts the process via `cmd1.Start()`.
- Checks `cmd1.ProcessState == nil`, which evaluates to `true` because the process has not yet exited.
- Calls `cmd1.Wait()` to wait for exit.
- Checks `cmd1.ProcessState == nil` again, which now evaluates to `false`.
- Queries `pState := cmd1.ProcessState`:
  - `pState.String()`: string summary (e.g. `exit status 0`).
  - `pState.ExitCode()`: numeric exit code.
  - `pState.Exited()`: boolean flag confirming exit.
  - `pState.Pid()`: process ID.
  - `pState.Sys()` and `pState.SysUsage()`: OS-specific process usage structure (`*syscall.Rusage`).
  - `pState.SystemTime()`: CPU time spent in kernel mode.
  - `pState.UserTime()`: CPU time spent in user mode.

## Key excerpt

```go
	if err := cmd1.Start(); err != nil {
		panic(err)
	}

	fmt.Println("PID=", cmd1.Process.Pid)
	fmt.Println("Process State is (Nil) =", cmd1.ProcessState == nil)

	err := cmd1.Wait()

	fmt.Println("Process State is (Nil) =", cmd1.ProcessState == nil)

	pState := cmd1.ProcessState
	fmt.Println(pState.String())
	fmt.Println(pState.ExitCode())
	fmt.Println(pState.Exited())
	fmt.Println(pState.Pid())
	fmt.Println(pState.SystemTime())
	fmt.Println(pState.UserTime())
```

## Things to watch

- **ProcessState timing:** `ProcessState` is completely unpopulated (`nil`) while the process is actively executing. Attempting to call methods on `cmd.ProcessState` before `Wait()` causes a `nil` pointer dereference panic.

## Terms

- **ProcessState:** A struct in Go's `os` package that stores information about an exited process returned by `Wait`.
- **User Time:** The cumulative time a CPU spends executing instructions in user space for a process.
- **System Time:** The cumulative time the operating system kernel spends executing system calls on behalf of a process.
